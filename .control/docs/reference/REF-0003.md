# Product requirements and scope

## Overview

This document records what Motioner must do and separates confirmed
requirements from open questions. REF-0001 describes how the system is
built; this document describes the product. The 1.0 scope below was
approved by the user on 2026-10-31.

## 1. Users and pillars

- Three audiences: non-technical creators working by chat, professional
  motion designers, and technical developers/artists.
- AI-first authoring: chat is the primary path.
- A real editor for fine control, not an afterthought.
- Code is visible and editable by the user.
- Public, free and Apache-2.0, with a path to revenue.
- Deterministic, high-performance local rendering.
- Long-term north star: After Effects parity except importing AE
  projects, plus Manim-class programmatic animation.

## 2. Authoring surfaces

- Chat agent with tools, preview rendering and automatic iteration.
- Timeline/editor with AE-style panels.
- Node graph for compositing, as an alternate view of the same document.
- Python-like MDF code with variables, functions, conditionals and
  loops that execute to build or drive compositions.

All surfaces mutate the same document through typed commands.

## 3. Confirmed feature scope

| Area | Requirement |
|---|---|
| NLE | Cut, trim and edit video and audio on a timeline |
| Audio | Full mixer with effects; no advanced mastering |
| 3D | Models, animation, particles; physics staged |
| AE parity | Everything except importing AE projects |
| Node graph | Required, alternate view over the same document |
| Import | Images, video, audio, SVG, glTF |
| Export | MP4 (H.264/AAC) and PNG sequence, 1080p primary |
| Publishing | User downloads the video and uploads it manually; no YouTube API |
| Code | Python-like, user-visible and editable, with executable control flow |
| AI providers | Anthropic, OpenRouter, Google |
| AI iteration | Render preview, inspect, refine automatically; human approves final render |
| Platforms | Windows first; other platforms later |
| GPU | GPU-accelerated; 1080p 60 fps preview |
| Quality | Full quality except while scrubbing; scrubbing may proxy |
| License | Apache-2.0, public and free; revenue model open |
| Team | Solo developer |
| CI | Tests without a GPU |
| Assets | Repo assets permissive; users import what they have rights to |

## 4. Confirmed 1.0 scope

Windows only, 1080p-first.

- 2D motion graphics: shapes, text, images, video and audio layers.
- AE-style timeline, keyframes and curves, masks, mattes, precomps,
  adjustment layers, effects.
- Basic node graph compositing.
- NLE: cut, trim, arrange, transitions and sync for video and audio.
- Audio: stereo tracks with volume, pan, fades and a basic effects chain;
  no advanced mastering.
- 3D: glTF models, cameras, lights, PBR, skeletal animation, GPU
  particles.
- Python-like MDF code with executable loops, conditionals and functions.
- AI chat, preview rendering, visual critique and automatic iteration.
- MP4 and PNG export at up to 1080p; YouTube upload is manual.
- CPU test suite plus manual GPU golden frames on the reference machine.

After 1.0: 1440p/4K, rigid-body physics, color grading, advanced audio
mastering, HDR, macOS/Linux, plugin API, collaboration, cloud rendering,
cloth and fluids.

## 5. Reference hardware

| Component | Specification |
|---|---|
| CPU | AMD Ryzen 5 8645HS, 6 cores / 12 threads, up to 4.3 GHz |
| RAM | 8 GB total (7.3 GB usable) |
| Discrete GPU | NVIDIA GeForce RTX 4050 Laptop, 6 GB VRAM |
| Integrated GPU | AMD Radeon 760M |
| Display | 1920x1080 |
| OS | Windows 11 Home, build 26200 |
| Storage | KIOXIA 512 GB NVMe SSD |

Implications: 1080p is the primary target; 4K is deferred. RAM and VRAM
budgets are mandatory, the app must request the high-performance NVIDIA
adapter, and scrubbing uses proxies while playback stays full quality.

## 6. AI workflow

- Cloud providers are allowed; project data and rendered frames may be
  sent to Anthropic, OpenRouter and Google, subject to their terms.
- The AI can request preview renders and inspect the resulting images to
  critique and refine its own work.
- The final render requires human approval.
- Motioner does not upload to YouTube; the user downloads the export.
- Iteration limits and cost controls are proposed but not fixed.

## 7. Licensing and distribution

- License: Apache-2.0.
- Public and free.
- Revenue model: open; must be compatible with Apache-2.0.
- Bundled assets: permissive licenses only (CC0, OFL, Apache, MIT).
- User imports: the user is responsible for rights.
- AI outputs: subject to provider terms.

## 8. Open questions

1. Code semantics: is MDF an executable program that generates the scene
   (Manim-style), or a document with executable script blocks?
2. Is "Python-like" a custom deterministic DSL or actual embedded
   Python?
3. Is LaTeX/math typesetting required to surpass Manim?
4. Which revenue model: donations/sponsors, paid cloud services, paid AI
   credits, support or marketplace?
5. Iteration budget defaults: maximum iterations, time and cost.
6. Audio effects included in 1.0 beyond volume/pan/fades: EQ, compressor,
   limiter, reverb, delay?
7. UI language in 1.0: English only or English plus Spanish?
8. Packaging: MSI/NSIS, portable ZIP, auto-update?
9. Rigid-body physics strictly post-1.0?
10. Node graph depth in 1.0: basic compositing only?

## 9. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Full scope with a solo developer | High | Staged 1.0, explicit post-1.0 list |
| Python-like executable code and UI round-trip | High | Resolve code semantics before the DSL |
| 8 GB RAM / 6 GB VRAM | High | 1080p-first, proxies, pooling, budgets |
| AI cost and runaway iteration | High | Budgets, cancellation, approval gates |
| Physics determinism | Medium | Bake simulations, fixed step, tolerance |
| Apache-2.0 and revenue | Medium | Revenue from services/cloud, not license fees |
| Asset licensing | Medium | Permissive policy and clear user responsibility |
