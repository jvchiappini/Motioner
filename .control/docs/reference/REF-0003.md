# Product requirements and scope

## Overview

This document captures the user's product answers from 2026-10-31 and
separates confirmed requirements from open questions. It is the input
for the ADR set D-0010 onward and for the roadmap revision. The system
blueprint (REF-0001) describes how Motioner is built; this document
describes what it must do.

## 1. Users and product pillars

Confirmed:
- Three audiences: non-technical creators working by chat, professional
  motion designers, and technical developers/artists.
- AI-first authoring: chat is the primary path.
- The editor exists for fine control, not as an afterthought.
- Code is visible and editable by the user; authorship must be excellent.

Product pillars:
- AI-first creation with automatic iteration until the result is good.
- Professional editor with After Effects-level control.
- Everything expressible as clean, readable code.
- Deterministic, high-performance local rendering.
- Public, free, with a path to revenue.

## 2. Authoring surfaces

- Chat agent with tools and preview feedback.
- Timeline/editor with AE-style panels.
- Node graph for compositing/effects.
- MDF code panel and on-disk project files.

All four mutate the same document through typed commands.

## 4. Reference hardware

The user's PC is the reference machine for performance work:

| Component | Specification |
|---|---|
| CPU | AMD Ryzen 5 8645HS, 6 cores / 12 threads, up to 4.3 GHz |
| RAM | 8 GB total (7.3 GB usable) |
| Discrete GPU | NVIDIA GeForce RTX 4050 Laptop, 6 GB VRAM |
| Integrated GPU | AMD Radeon 760M |
| Display | 1920x1080 |
| OS | Windows 11 Home, build 26200 |
| Storage | KIOXIA 512 GB NVMe SSD (477 GB) |

Implications:
- 8 GB of RAM is tight for 4K video, frame caches and AI previews;
  memory budgets are mandatory.
- 6 GB of VRAM limits 4K intermediates and effect chains; the renderer
  needs pooling and graceful degradation.
- The laptop uses hybrid graphics; the application must request the
  high-performance NVIDIA adapter explicitly.

## 5. Performance and quality policy

Confirmed:
- Target 1080p at 60 fps preview on the reference machine.
- Quality drops only while scrubbing; playback and export use full
  quality.
- Renders target 4K offline.

Proposed:
- Same-machine determinism is exact; cross-machine determinism is
  documented with tolerance.
- CI runs evaluation, format and logic tests on CPU; rendering tests are
  golden-frame checks generated on the reference machine and verified
  manually or in a separate GPU job.
- The editor never blocks input for decode, AI or export.

## 6. Delivery and monetization

Confirmed:
- Public and free.
- Revenue is required eventually.
- Solo developer.

Open:
- License: permissive, copyleft or source-available.
- Revenue model: donations/sponsors, paid cloud rendering, paid AI
  credits, marketplace or services.
- Whether paid features are separate from the open core.

## 7. Proposed 1.0 (not confirmed)

A realistic solo-developer 1.0 that still delivers the product promise:

- Windows only.
- 2D motion graphics: shapes, text, images, video, audio.
- AE-style timeline plus a basic node graph.
- NLE: cut, trim and arrange video/audio; audio tracks with volume,
  pan, fades and a basic effects chain.
- 3D: glTF models, cameras, lights, PBR, skeletal animation, GPU
  particles; rigid-body physics after 1.0 if needed.
- Effects, masks, mattes, precomps, adjustment layers.
- MDF code, full round-trip, AI chat and automatic iteration on previews.
- MP4 and PNG export, YouTube upload.
- CPU test suite and manual GPU golden tests.

Post-1.0: advanced physics (cloth, fluids), full AE parity, HDR,
macOS/Linux, plugin API, collaboration, cloud rendering.

## 8. Open questions

1. Is the proposed 1.0 staging acceptable, or must every feature be in
   1.0?
2. Which license and revenue model?
3. What does "everything must be allowed" mean for bundled assets and
   AI providers' terms?
4. MDF syntax, visible IDs and comment preservation.
5. Node graph role: full compositing graph or effects graph beside the
   layer timeline?
6. AI privacy, API key storage and automatic iteration budgets.
7. NLE and audio depth: transitions, color grading, loudness, effects.
8. Physics and particles: engine, determinism and priority.
9. YouTube: direct upload from the app or export plus manual upload?
10. UI language and packaging.

## 9. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Full AE parity plus NLE plus physics for one developer | High | Stage 1.0; keep the north star explicit |
| 8 GB RAM / 6 GB VRAM | High | Strict budgets, proxies, pooling, skip frames |
| Physics determinism across GPUs | High | Bake simulations, fixed step, tolerance policy |
| AI cost and runaway iteration | High | Per-task budgets, cancellation, approval gates |
| Asset licensing ambiguity | High | Clear bundled-asset policy, user responsibility for imports |
| YouTube API quotas and OAuth | Medium | Resumable upload, clear scopes, manual fallback |
| License inconsistent with revenue | High | Decide before accepting contributions |
