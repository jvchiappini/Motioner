## Contexto

`bake` (D-0022) only folds overrides of nodes bound to a top-level variable,
by appending `var.prop = value` statements. Nodes created in loops or
functions (the five circles and the spinners of `hello.motion`) are refused,
so their overrides live in the overrides file forever. Discussed in session
012/013: a hybrid bake that edits the program in place when that is exact,
and keeps overrides otherwise. Not built in session 013 by design.

## Design

1. Provenance already records the creating call's span and, through the
   interpreter, could record the span of each literal argument that set a
   property (`circle(radius=24, ...)`, `dot.pos = (480 + i * 240, 820)`).
   Extend provenance with **value origins**: for each (node, property) the
   source span of the expression that produced the value, and whether it is
   a plain literal.
2. A literal is **private** to a node when it is evaluated for that node only:
   not inside a loop body, not inside a function called more than once, not
   shared through a variable used by other nodes. The interpreter can count
   evaluations per span during one run; private means count == 1.
3. Bake per override:
   - static value, private literal → replace the literal text in place
     (numbers with `format_number`, strings with `quote`, pairs as `(x, y)`);
   - keyframe on a node whose `.key(...)` call for that time is a private
     literal call → edit that call's arguments;
   - anything else (shared literal, computed value, loop-created node) →
     today's behaviour: append to the generated block if bound, otherwise
     keep the override.
4. Exactness check (as today): `run(baked) == run(program) + overrides`; if
   the check fails for an edit, fall back to keeping the override.
5. Edits are applied from the end of the file backwards so earlier spans stay
   valid; the overrides that were baked are removed in one atomic write.

## Criterios de aceptacion
- [x] Value origins recorded by the interpreter, deterministic, with tests.
- [x] Private-literal detection (loop and multi-call cases refuse).
- [x] In-place edits for static values and private key calls; fallback kept.
- [x] `bake` exactness test over every override kind; idempotent.
- [x] Spec §9.3 and D-0022 addendum (or a new ADR) describe the rules.

## Notas del agente

Implemented in `crates/motioner_dsl/src/origins.rs` and `bake.rs`; D-0027 has
the value-origin model, the private-literal rule and the exact re-keying of
remaining overrides by the edit offsets. The editor's `bake` and `motioner
bake` share it. The exactness check compares semantics (identities shift with
in-place edits by design), and the fallback pass restores the D-0022
behaviour.

Byte-offset provenance keys shift after an in-place edit; bake re-keys the
remaining overrides with the edit offsets (not with the Phase 2 suggestions).
