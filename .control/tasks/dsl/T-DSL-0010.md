## Contexto

Prompt 12 phase 4 (D-0036 section 2.3): when a node is created or written
inside a user function, the planner must specialise the call site instead of
falling back to an override. Touches `motioner_dsl` (`plan`, a new call-site
module, loop guards with calls) and the MDF language (default parameters).

## Criterios de aceptacion
- [x] A value that is a parameter of the function is passed (or edited) as a
      keyword argument at the edited call site.
- [x] A function that returns the node gets the call result bound when needed
      and an assignment right after the call; repeating the edit replaces that
      assignment.
- [x] Otherwise the old literal is promoted to a keyword parameter with that
      default, the literal becomes the parameter and the call site passes the
      new value; other call sites render identically (verified).
- [x] Functions called from a loop bind the result and add a loop guard after
      the call (`b = badge(i)` / `if i == 3: b.fill = ...`); values written
      inside a function from a loop use the same guard.
- [x] Nested calls and inline calls in the middle of an expression fall back
      with a reason; no silent guess.
- [x] MDF supports default parameter values (`def f(x, fill="#ffffff")`),
      parsed, interpreted, documented in `spec/mdf-v0.md`, with tests.
- [x] Planner tests cover each strategy, CRLF/indentation and a refusal.
- [x] Bench baseline `af1115d` vs the current tree back to back (20 warm-up +
      200 runs, median/p90); median no more than 7 % above baseline.
- [x] Full gate green; no commit.

## Notas del agente

- `crates/motioner_dsl/src/call_site.rs`: new strategy module. Chooses from
  the edited write's origin: `Parameter` (pass/edit an argument), `returns_node`
  (bind + assign after the call), otherwise promote the literal. Appends
  arguments preserving single-line/multiline layout and CRLF.
- `loop_guard` now accepts calls: selects the caller binding inside the loop
  body, seeds the insertion after the call statement (creating a binding for
  an unbound call) and keeps the normal guard/merge/removal paths.
- MDF default parameters: `ast::Param`, parser rules (no required after a
  default), `bind` required count, call-time evaluation in caller scope,
  `ParameterOrigin.default` span. Tests `tests/default_parameters.rs`.
- Planner tests: `tests/planner_calls.rs` (18 cases: keyword/positional,
  returns/bind/repeat, promotion with pair/default/CRLF, loop bound and
  unbound, value written in a function, nested/expression/computed refusals,
  key value).
- Bake's old spinner fallback test became `an_in_place_edit_and_a_call_override_both_become_code`
  because phase 4 now writes that override as code.
- Benchmark, same host back to back (two pairs): baseline `af1115d` median
  1.207 / 1.221 ms, current 1.161 / 1.234 ms; worst +1.1 % (budget +7 %).
  p90 1.692/1.700 -> 1.635/1.527 ms. Nodes 84, origins 649.
- Gate green: fmt, clippy pedantic, workspace tests, rustdoc, boundaries,
  machete, `pctl validate`, `doc-check-refs`. Disk cleaned back to 12.4 GB.
