## Contexto

Phase 1 of prompt 12 (D-0036): the write-through planner needs to know where a
node was made and how it was reached, not only which literal fed a property.

`motioner_dsl::origins` now records, for every node creation and every
property/key write: the creation and write statements, the enclosing block
(span and indentation), the binding and whether it is assigned again later in
that block, the loop stack (span, variable, iterable span, iteration index and
literal value, body span/indent) and the call stack (call site, definition,
parameters and defaults, whether the invocation returned the node). Each
expression is classified as a literal, a parameter, a loop variable or
computed. Names are interned as `NameId`; the loop/call context is shared
through `Arc`, so recording stays cheap and `Execution` remains `Send`.

Parser change: `for`/`if` statements now span their whole construct instead of
only the keyword token, so loop and block spans are usable.

Measured on `showcase_pro.motion` (release, 84 nodes, 647 origins):
0.80 ms/run before, ~1.5 ms/run after (interpreter only).

## Criterios de aceptacion
- [x] Every node creation records statement, block, binding, loops and calls.
- [x] Every value/key origin records statement, block and expression class.
- [x] Loop stack records index and literal iteration value; call stack records
  parameters and whether the call returned the node.
- [x] `tests/origins_v2.rs` covers top level, reassignment, loops, nested
  loops, functions, loop variables and keys.
- [x] Interpreter cost measured before/after on `showcase_pro.motion`.
- [x] Gate green (fmt, clippy pedantic, tests, rustdoc, boundaries, machete,
  `pctl validate`).
