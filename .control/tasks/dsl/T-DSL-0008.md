## Contexto

Phase 2 of prompt 12 (D-0036). `motioner_dsl::CodeEdit` is an ordered,
non-overlapping set of byte replacements with a summary and strategy; it can
apply, invert for byte-exact undo, compose, re-key provenance identities and
re-key override sets (the D-0027 offset arithmetic, now shared by bake).

`plan(program, origins, document, change)` accepts the resolved
`motioner_core::EditCommand` and returns `Plan::Code` or
`Plan::Fallback(reason)`. It implements strategy 1 (private literal, moved
from bake) and strategy 4 (local assignment next to the node's last write,
editing an existing assignment instead of adding one). Every code plan is
verified by re-running the program and comparing the document by position.

`bake` now goes through `plan` for each override; refusals still use the
D-0022 generated block. The parser/reporting split keeps one implementation.
