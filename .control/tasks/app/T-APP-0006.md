## Contexto

Prompt 11 left a known gap: with audio playing and loop enabled, the mixer
reaches the end of its range and the playhead stayed on the last frame. The
device stream kept filling silence, so `AudioOutput::position` stopped
advancing.

Fix (prompt 12, phase 0.5): `AudioOutput::ended` reports that the device
consumed every mixed sample. `Transport::follow_audio` wraps a looping
transport to frame 0, re-anchors the clock and returns the loop-start frame;
the app then calls `restart_audio`, which mixes a fresh range from that frame
and restarts the cpal stream. The first sample after the wrap is the first
sample of the loop range (the start sample is computed with the same integer
arithmetic as playback). A non-looping stream now stops on the last frame
instead of playing forever.

## Criterios de aceptacion
- [x] `AudioOutput::ended` and `ProjectHost::audio_ended` expose the consumed
  range.
- [x] `Transport::follow_audio` wraps to the loop start and reports it.
- [x] The app re-mixes and restarts the stream at the loop start frame.
- [x] Headless tests fail without the wrap logic
  (`a_finished_audio_stream_restarts_looping_playback_at_the_first_frame`,
  `the_cursor_reports_the_end_only_after_the_last_frame`).
- [x] Gate green.

## Notas del agente

The loop start is frame 0; a future in/out range can pass a different frame to
the same restart path.
