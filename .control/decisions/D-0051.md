## Contexto

MDF has separate constructors per asset kind (`image("key")`,
`audio(...)`, `video(...)`) and `use()` existed only as a v0 proposal in
spec section 10 with no implementation. Character work needs one import
model: an SVG file, an image, a sound, a video, a font and a MDF helper
file must all be *definitions* that are instantiated by calling them, so
a re-run after the source file changes keeps every animation (parts are
addressed by stable ids, not by array position).

The DSL crate must stay file-system free: reading and parsing happen in
`motioner_io`, behind a resolver the host injects.

## Decision

- `use(path)` returns a **definition** whose kind is decided by the file
  extension (`.motion`, `.svg`, `.png/.jpg/.jpeg/.webp`, `.wav/.flac/
  .mp3/.ogg`, `.mp4/.mov/.mkv`, `.ttf/.otf`).
- Definitions are values with metadata attributes (`kind`, `width`,
  `height`, `duration`, `parts`, `functions`) and are callable:
  `art = use("assets/mascot.svg")` then `s = art(pos=(960, 540), scale=3)`.
  For images, calling instantiates the same node `image("key")` produces;
  `image("key")` stays as sugar and is byte-identical.
- `.motion` modules execute once per run in the shared global scope (v0
  import semantics, like a guarded `from module import *`) and return a
  namespace handle. Top-level `def`s are the module's exported
  definitions; calling `ns.mascot(...)` builds into the caller's
  document. Relative paths inside a module resolve against that module's
  directory. Cycles and repeated imports are detected by resolved path.
- Sandbox: the resolver root is the project folder (or the working
  directory for a loose file). Absolute paths and `..` escapes are
  rejected before any I/O, with a diagnostic at the `use()` call span.
  Module diagnostics are reported with the module path and the module's
  line in the message, and the call-site span.
- The DSL crate exposes `run_with_assets(...)` taking a
  `dyn AssetResolver`; `run`/`run_with_metrics` use a resolver that
  reports "use() needs an asset resolver". `motioner_io` implements the
  file-system resolver; tests use an in-memory one.
- Hot reload is "re-run the program": node identities are provenance
  keys derived from the program position, so unchanged parts keep their
  identity, selection and keys; a changed module re-executes and the
  document is rebuilt deterministically.

## Consecuencias

Gana:
- One mental model for every external resource; the UI Assets panel, the
  agent tools and the code panel all speak `use()`.
- Definition metadata gives agents and the inspector concrete facts.

Se pierde:
- v0 modules are imported into one global scope; two modules that export
  the same top-level name shadow each other (documented, later fixed by
  namespaced globals if it hurts).
- The resolver is injected at the `run_*` entry point, so callers that
  need `use()` must opt in; this keeps the crate file-system free.

Pendiente:
- Namespaced module globals, `export` lists, and `use()` of glTF/Lottie
  (backlogged with the 3D and Lottie tasks).
