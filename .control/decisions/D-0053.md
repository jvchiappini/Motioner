## Contexto

The reference mascot controller has 17 hand-written *partial poses* that
are tweened onto the current parameter set, two keyframed clips in
`[start, duration, ease, partial pose]` form, a blink, and a look pad. A
Rive-class rig needs the same vocabulary plus state machines whose inputs
can also be keyed on the timeline.

## Decision

- **Pose**: named partial property set declared on the rig
  (`r.pose("happy", mouth_open=9, lid_bottom=0.3)`). Applying is
  `m.pose("happy", at=1.0, dur=0.35, ease="quad_out")`: the transition
  starts at `at`, blends every listed property from its value at `at` to
  the pose value over `dur`, and leaves unlisted properties untouched.
- **Blend math per property type**: floats/vec2 lerp, angles slerp along
  the shortest arc, colours lerp in linear-light space, bools and enums
  step at the transition end. Eases are the existing `motioner_core`
  named eases plus `bezier(...)`.
- **Clip**: `cl = r.clip("jump")` then `cl.key("squash_y", 0.28, -60,
  ease="quad_out")`; a clip is a reusable keyed sequence of property
  values. `m.play("jump", at=4.0, loops=2, speed=1.0)` bakes its samples
  into the property curves. Clips can be played more than once and
  offset in time.
- **Layers**: `r.layer("blink", mode="override")` returns a layer that
  owns poses/clips and plays on top of the base state with an optional
  per-property mask (default: every property it writes). Override wins
  over base; additive adds to the base when enabled. Procedural layers
  (`r.blink(every=3.5, jitter=0.6)`) emit deterministic blink clips from
  a fixed seed.
- **State machine**: inputs (`r.input("mood", "calm", kind="enum",
  values=[...])`, number and bool variants), states that hold a pose or
  a clip, and transitions `r.transition(a, b, input="mood",
  equals="sad", dur=0.3, exit=0.0)`. Any-state transitions use
  `r.transition("*", "hit", trigger="jump")`. Events are emitted on
  transitions and clip markers with the frame they happen on.
- **Timeline integration**: machine inputs are properties, so they are
  keyed on the instance (`m.mood.key(6.0, "sad")`, `m.jump.fire(4.0)`)
  and evaluated frame by frame during the bake. Entry state at frame 0
  is the declared default; with no keys the machine is constant.
- **Baking and backwards scrubbing**: poses, clips and machine
  transitions are sampled at every frame in order, so the document holds
  a key per frame and seeking backwards is exact (the rule is "bake is
  stateless; there is no runtime state to rewind").

## Consecuencias

Gana:
- The HTML's 17 presets map 1:1 to poses, its two ANIM tables map 1:1 to
  clips, and its blink/look helpers map to a layer and a constraint.
- One evaluation order, one easing implementation, testable in isolation
  in `motioner_rig`.

Se pierde:
- Pose tracks are baked, not kept as a separate document track; the
  editor timeline shows the resulting keys (property rows are exposed by
  the rig manifest).
- Additive layering is limited to numeric properties; colour addition
  is not allowed (documented).

Pendiente:
- Blend states 1D/2D by input, interrupts/exit-time policies beyond the
  simple step-and-blend and editor pose thumbnails.
