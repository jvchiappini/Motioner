## Contexto

The user wants code that is visible, editable, Python-like, and able to
run loops and logic to surpass Manim. This conflicts with the original
D-0003 model in which the document is the truth and code is only a
lossless projection: arbitrary executable logic cannot always be
projected back from an edited scene.

## Decision

Proposed, pending user confirmation of the semantics.

MDF is a Python-like language with indentation, variables, functions,
conditionals and loops. Execution is deterministic and sandboxed: no
I/O, no network, no ambient time, bounded resources.

Recommended semantics: program-first with an editable evaluated
document.

- The MDF program is the canonical source and executes to build the
  scene, like a Manim scene.
- Execution produces a document snapshot with provenance links from
  scene elements back to source spans.
- UI edits on generated elements become structured overrides keyed by
  stable identity, or "bake" the element, and are written back to MDF.
- Orphaned overrides are reported rather than silently dropped.
- The AI can edit the program, add overrides, or both.

Alternative: keep the document as the truth and allow executable script
blocks that generate content which is baked into the document on edit.

## Consecuencias

Program-first gains:
- Real loops, functions and procedural generation.
- Capability beyond Manim, with a text-first source.
- Clean diffs and version control.

Program-first costs:
- UI round-trip for generated elements is hard and needs overrides.
- The document becomes a compiled artifact with provenance, revising
  D-0003.
- The language runtime, sandbox and limits are a large subsystem.

Pending:
- Confirm program-first versus document with script blocks.
- Decide custom DSL versus embedded Python.
- Define the override and bake model.
- Define the language surface and its scene API.
