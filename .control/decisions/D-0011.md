## Contexto

The user wants code that is visible, editable, Python-like, and able to
run loops and logic to surpass Manim. That conflicts with D-0003, where
the document is the truth and code is only a projection: arbitrary
executable logic cannot always be projected back from an edited scene.
The user chose program-first on 2026-10-31.

## Decision

MDF is a Python-like executable language and the canonical source of a
composition.

- Syntax is Python-like: indentation, variables, functions,
  conditionals, `for` and `while` loops, expressions, collections and
  calls.
- MDF is a custom, deterministic DSL, not embedded CPython.
- Execution is sandboxed: no filesystem, network, process, ambient time
  or unseeded randomness; resource limits apply.
- Running a program produces a scene snapshot with provenance links from
  elements back to source spans.
- The editor displays the snapshot. UI edits become structured overrides
  keyed by stable identity, or explicitly bake an element, and are
  written back to MDF.
- Orphaned overrides are reported, never silently dropped.
- The AI can edit the program, add overrides, or both, through typed
  commands.
- LaTeX math typesetting is part of the 1.0 language surface (D-0016).

D-0003 is superseded. The document is a compiled artifact plus
overrides; the MDF program is the truth.

## Consecuencias

Gains:
- Real loops, functions and procedural generation, beyond Manim.
- A text-first, diffable, version-controlled source.
- One language for disk, code panel and AI.

Costs:
- The document model becomes a compiled artifact with provenance.
- UI round-trip needs a rigorous override and bake model.
- The parser, interpreter, sandbox and resource limits are a large
  subsystem.
- Actual Python libraries are not available in 1.0.

Pending:
- MDF v0 grammar and scene API.
- Override and bake semantics in detail.
- Interpreter implementation strategy and performance budget.
- Whether a Python bridge is added later.
