## Context

Phase 4 needs seven node blend modes: `normal`, `add`, `multiply`, `screen`,
`overlay`, `darken` and `lighten` (D-0028).  FerrousEngine is a general engine:
the capability must be useful to any 2D consumer, with no Motioner concepts in
its API.

The Pure2D pass already had a per-draw `BlendMode2d` with four modes, expressed
as fixed-function `wgpu` blend states, plus offscreen layers (`Layer2d`) whose
composite also used those states.  `overlay`, `darken` and `lighten` cannot be
expressed by blend factors: their result is a function of the destination
colour, and a render pass cannot sample its own attachment.

## Decision

1. **Keep per-draw blending fixed-function.**  `BlendMode2d` stays the four
   modes that map to `wgpu::BlendState`; it remains the cheap path for a
   self-contained draw.
2. **Add `CompositeMode2d`** (seven modes) for layers.  The first four are
   exactly the fixed-function states; the last three are backdrop-aware.  The
   array/`Layer2d` API stays source-compatible: `Layer2d::new` takes
   `impl Into<CompositeMode2d>`, and `BlendMode2d` converts into it.
3. **Backdrop snapshot + dedicated composite pass** for the three advanced
   modes.  When a plan reaches one, the renderer:
   1. ends the current pass after the preceding draws;
   2. `copy_texture_to_texture` the destination into a scratch texture;
   3. runs a full-target pass that samples the layer and the snapshot with
      blending disabled and writes the composited premultiplied colour.
   The split is per plan (root or nested layer), so advanced modes work at any
   layer depth.  Plans without advanced modes keep the single-pass path.
4. **Math** (premultiplied linear light, straight source `s`, backdrop `b`,
   coverage `As`/`Ad`):
   `Co = Cs*(1-Ad) + As*Ad*B(b,s) + Cd*(1-As)`, `Ao = As + Ad*(1-As)`;
   `B` is `min` (darken), `max` (lighten) or the overlay branch conditioned on
   the source (`s < 0.5 ? 2bs : 1 - 2(1-b)(1-s)`), matching D-0028.
5. **General API only**: `CompositeMode2d`, `Layer2d::new`, the backdrop
   pipeline and the `render_to_texture_view` entry point are engine concepts.
   Motioner maps `BlendMode` names onto them and decides *which nodes* become
   layers.

## Consequences

- One full-target copy and one extra full-target pass per backdrop-aware
  composite.  Fixed modes cost nothing; the feature is pay-per-use.
- The destination texture must have `COPY_SRC` (headless targets do; the
  engine already configures surfaces with it for screenshots).  With
  `render_to_view` (view only) advanced modes fall back to `Normal` with a
  warning; `render_to_texture_view` is the supported entry point.
- The target must be single-sampled (Pure2D targets are).  This is documented
  in `crates/ferrous_2d/docs/blend.md`.
- Layers remain the base for Phases 5 and 6: effects and masks render a subtree
  into an offscreen layer and composite it back, reusing the same snapshot
  machinery for the backdrop where a mask needs it.
- Migration note: `Layer2d` gained a field-like type change (`blend` is now
  `CompositeMode2d`).  Struct literals must use `CompositeMode2d` or
  `.into()`; `Layer2d::new` calls keep compiling.
- Motioner keeps overlay/darken/lighten behind `RenderError::Unsupported` and
  the temporary `engine-composite` feature until the engine pin is bumped.
  Text gradients follow the same pattern with `engine-text-gradient`.
- The 7-mode golden, `examples/blend.motion` and the inspector grid are built
  now; the golden is generated against the clone and skips on the pin.
