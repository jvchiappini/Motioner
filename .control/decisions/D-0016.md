## Contexto

Manim's core is mathematical animation. The user wants Motioner to
surpass Manim, and confirmed that Motioner must render LaTeX. Requiring
a system LaTeX installation would break portability and determinism.

## Decision

Approved by the user on 2026-10-31.

- 1.0 supports LaTeX math in text layers, inline and display.
- The renderer must be deterministic, self-contained and GPU-friendly;
  no shelling out to a system LaTeX installation.
- Preferred approach: a Rust-native LaTeX math renderer that produces
  vector outlines for the existing MSDF/path pipeline.
- A bundled JS/MathJax path is a fallback only if the native route cannot
  cover the required command set.
- Scope is math typesetting, not full LaTeX documents: common symbols,
  fractions, roots, sums, integrals, matrices, accents, alignment and
  common fonts.
- Math is animatable like any text or vector element.

## Consecuencias

Gains:
- Math animation without external dependencies.
- Deterministic rendering and export.
- A direct path to Manim-class educational content.

Costs:
- A new parser/layout engine for math.
- Font coverage and typography quality work.
- The supported command set must be documented and tested.

Pending:

- Required command set and font bundle.
- Fallback policy and error messages for unsupported commands.
