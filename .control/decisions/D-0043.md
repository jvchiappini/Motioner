## Contexto

D-0041 fixes the harness and lists tool families; D-0036 requires
`motioner tools --schema` as the single published tool list; D-0040 trains
the Motioner model on trajectories that use these tools. The catalogue must
be stable, small enough for a small model, exact enough for verification, and
identical for every provider, external agents and the training data.

## Decision

### 1. Principles

- One catalogue, generated from Rust definitions (name, description,
  parameter schema, result schema, example, cost class). `motioner tools
  --schema` prints it as JSON Schema; the harness converts it to each
  provider's tool format. A test fails when a tool lacks a description,
  example or result schema.
- Tools are few and orthogonal. Editor commands are **not** one tool each:
  `run_commands` takes D-0024 command text, so the 45+ commands cost one tool
  definition and the training data uses the same text as `motioner edit`.
- Every mutating tool returns the code diff, the write-through strategy
  (D-0036), the verification result, the ids it created or touched and the
  undo checkpoint. Failures are typed, actionable and never partial: a batch
  is all or nothing.
- Results are compact JSON text with stable field names; images travel as
  image content next to the JSON (PNG), never as base64 inside the JSON.
- Deterministic: the same project state and arguments give the same result,
  so sessions replay as training data.
- Each tool declares a cost class (`cheap`, `render`, `analysis`, `user`) that
  the harness counts against the D-0012 budgets.
- Parameters accept node ids (`.id()` or provenance key), names, or set-of-
  marks numbers from the last overlay (`"#7"`).

### 2. Catalogue v1

**Project and code (cheap)**

| Tool | Parameters | Returns |
|---|---|---|
| `project_summary` | — | comps, size, fps, duration, theme, tempo, scenes, layer count, assets, pending overrides, MDF and `std` versions |
| `outline` | `comp?`, `depth?`, `filter?` | node tree: id, name, kind, time range, parent, visible |
| `get_node` | `id`, `frame?` | properties (static or keyed), keys, effects, masks, bounds, code location (file, line, statement) |
| `read_program` | `file?`, `start_line?`, `end_line?` | numbered source lines |
| `search_code` | `query`, `regex?` | matches with file and line |
| `selection` | — | selected ids, playhead frame, visible time range |
| `std_reference` | `name` | signature, parameters, defaults, example and preview path of a `std` function, preset, theme or component |
| `find_examples` | `query`, `limit?` | curated examples: brief, features, path, contact sheet path |

**Editing (mutating)**

| Tool | Parameters | Returns |
|---|---|---|
| `run_commands` | `commands: [string]`, `scope?` (`this`/`all`) | per command result, diff, strategy, ids, checkpoint |
| `apply_code_edit` | `file`, `edits: [{start_line, end_line, new_text}]` or `{old_text, new_text}` | diff, diagnostics, verification, checkpoint |
| `write_file` | `file`, `contents` (new composition or module only) | diagnostics, checkpoint |
| `run_program` | — | diagnostics with spans and suggestions, run time |
| `format` / `lint` | `file?` | diff / diagnostics with fixes |
| `checkpoint` | `name` | id |
| `restore` | `checkpoint` | diff back to it |
| `undo` / `redo` | `steps?` | diff |

**Seeing (render)**

| Tool | Parameters | Returns |
|---|---|---|
| `render_still` | `frame` or `time`, `size?` (long edge, default 768), `overlay?` (`none`, `marks`, `safe`, `grid`, `bounds`), `ids?` | image + mark legend (`#n` → id, name) |
| `render_filmstrip` | `start`, `end`, `count?` (≤ 8), `overlay?` | one strip image + frame list |
| `render_contact_sheet` | `count?` (≤ 12) | one grid image + frame list |
| `render_zoom` | `frame`, `region` (x, y, w, h in comp pixels), `size?` | image |
| `compare` | `a`, `b` (checkpoints or frames), `mode?` (`side`, `diff`) | image + changed regions |
| `view_asset` | `key`, `frame?`, `size?` | image (+ asset metadata) |
| `render_variants` | `variants: [{label, commands or edits}]` (≤ 4), `frame` | one grid image; variants are applied on throwaway copies, the project is unchanged |
| `view_editor` | — | screenshot of the editor viewport |

**Analysing (exact text twins, analysis)**

| Tool | Parameters | Returns |
|---|---|---|
| `describe_frame` | `frame`, `ids?` | visible elements: id, kind, box, colours, text, z, opacity |
| `check_design` | `start?`, `end?`, `rules?` | D-0040 rubric issues: rule, severity, ids, frames, measured value, suggested fix |
| `motion_report` | `ids?`, `start?`, `end?` | per element: onsets, durations, peak speed, velocity jumps, eases; global: stagger, dead time, overload |
| `layout_report` | `frame` | overlaps, safe-area violations, alignment groups, hierarchy |
| `legibility_report` | — | per text: on-screen time vs reading time, contrast against the real background |
| `hit_test` | `frame`, `x`, `y` | ids under the point, topmost first |
| `code_for_node` / `node_for_code` | `id` / `file`, `line` | statement location / ids it creates |
| `sample` | `id`, `property`, `frames` | values |

**Media understanding (analysis)**

| Tool | Parameters | Returns |
|---|---|---|
| `analyze_image` | `key` | size, dominant palette, salient region, empty regions ranked for text, average luminance per region |
| `analyze_video` | `key` | duration, fps, scene cuts, motion intensity curve, calm segments |
| `analyze_audio` | `key` | duration, bpm, beat and downbeat times, sections, loudness curve |

**Resources (cheap or mutating)**

| Tool | Parameters | Returns |

**User (user)**

| Tool | Parameters | Returns |
|---|---|---|
| `ask_user` | `questions: [{question, options: [{label, description}], recommended, multi?}]` (≤ 3) | answers |
| `ask_user_visual` | `question`, `variants` (from `render_variants`) | chosen label |

| Tool | Parameters | Returns |
|---|---|---|
| `render_preview` | `start?`, `end?`, `quality?` (`low` default) | path, duration, sampled frames image |
| `export` | `path?`, `format?` | requires `request_approval` in the same turn; path and stats |

### 3. Image budget

- Defaults: stills 768 px long edge, zoom 768, strips and sheets 1536 wide;
  the agent may ask for up to 1568 px. PNG, sRGB.
- Rendered images are cached by (program hash, frame, size, overlay).
- Per turn and per task image limits are part of the budget; the harness
  tells the model how many image calls remain.
- Text twins are listed first in the system prompt: verify with
  `check_design`/`describe_frame`, use images for taste and user media.

### 4. Versioning

The catalogue has a version. Adding a tool or an optional parameter is
minor; renaming, removing or changing a result field is major and needs a
migration note for the Motioner model (D-0041 §6).

## Consecuencias

Gana:
- One small, stable catalogue (~45 tools, commands batched) for every
  provider, the local model, external agents and training.
- Mutations always show their code; analysis is exact; vision is budgeted.

Se pierde:
- The catalogue is an API: changes need versioning and model retraining.
- Several tools (`analyze_audio`, `analyze_video`, `render_variants`) need
  real implementation work before the agent is complete.

Pendiente:
- Exact JSON result schemas, written with the implementation (prompt 13/14).
- The bundled icon set and its licence (ADR when chosen).
