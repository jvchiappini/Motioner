## Contexto

Phase 6 needs masked text reveals and luma mattes. D-0031 and D-0032 already
give every node an offscreen layer with opacity, blend mode and an effect chain,
which is exactly the machinery a mask needs: the mask is a second image that
multiplies the finished layer before it composites.

The engine pin does not carry the mask pass yet, so Motioner has to ship the
whole document/DSL/eval/editor path now and refuse only the GPU pass, with the
same typed `Unsupported` pattern Phase 5 used.

## Decision

1. **A mask is a node relationship, not a content field.**
   `node.mask(source, mode="alpha"|"luma", invert=False)` stores a
   `MaskSpec { source, mode, invert }` on the masked node. `node.mask(None)`
   clears it. The editor writes it as the `mask` override
   (`"<source>:<mode>:<invert>"`, or `"none"`), so it survives a reload and
   shows in `query`; `bake` writes `var.mask(source, mode=..., invert=...)` or
   `var.mask(None)`.

2. **The source is not drawn on its own.** Evaluation skips a node used as a
   mask source in the normal stream and emits its subtree as a second item
   range attached to the masked node's `PlanLayer` (after the content, before
   the layer closes). A source is never composited directly; only its coverage
   is used.

3. **Order.** Content → effect chain → mask → group opacity/blend. A drop
   shadow is therefore clipped by the mask, and a blurred mask source feathers
   the edge: feathering is a `blur` effect on the source node, with the same
   `sigma = radius / 2` kernel as any other effect.

4. **Formulas.** Everything is premultiplied linear light:
   `coverage = mode == alpha ? m.a : dot(m.rgb, (0.2126, 0.7152, 0.0722))`,
   `coverage = invert ? 1 - coverage : coverage`, `out = content * coverage`.
   Luma reads the premultiplied colour, so a transparent mask pixel is black
   (coverage 0, or 1 when inverted).

5. **Coordinate space.** The source is evaluated in world space with its own
   animated transform. If it is a child of the masked node it inherits the
   masked node's transform and moves with it; a source elsewhere ignores the
   intermediate ancestors' transforms (only its own transform applies), so a
   moving mask is predictable.

6. **Cycle rules.** A node cannot mask itself, cannot be masked by an ancestor
   (the mask would draw the masked node again), and the mask graph (node →
   source) may not contain a cycle. `Document::can_mask` is the one rule;
   `set_mask` and the editor both use it.

7. **Registry.** The engine gets `Mask2d { mode, invert }`,
   `push_layer_2d_masked`, `begin_mask_2d`/`end_mask_2d`, a mask shader and
   `crates/ferrous_2d/docs/masks.md`; misuse is `LayerError::MaskSourceNotAllowed`,
   `MaskSourceMismatch`, `MaskSourceNotClosed`, `MaskWithoutSource`. Motioner
   put it behind a temporary `engine-masks` feature until the pin carried the
   pass. *Amended 2026-11-02:* pin e8b9ba7 carries it; the feature, the
   `Unsupported` precheck and the refusal tests are gone.

8. **Goldens.** `masks_alpha_reveal_f36.png` and `masks_luma_invert_f150.png`,
   with pinned SHA-256, per-pixel assertions (each mask's inside, outside and
   overlap pixel) and the D-0028 render comparison. `hello_f120.png` and the effect stills stay unchanged.

## Consecuencias

- A masked node always pays for one extra offscreen layer (the source) plus one
  full-target mask pass; nested masks multiply that, bounded by the engine's
  layer depth and effect budget.
- Masks compose with effects and blend modes without new per-draw state, and a
  source may carry its own mask, so nested mattes fall out of the same code.
- The pin bump only removed the temporary feature and the `#[ignore]` on the
  comparison; no document or editor change was needed.
