## Contexto

Timing is half of motion design. Phase 9 needs custom cubic-bezier easing with
CSS semantics, a `hold` step, four Penner curves, motion blur averaged in
linear light, and `stagger` / `wiggle` helpers. The existing `Ease` enum was a
plain `Copy + Eq + Hash` preset list, the evaluator only sampled integer
frames, and the engine had no way to average sub-frames on the GPU.

The prompt that requested this work called the record `D-0036`, but that ID is
already the accepted write-through decision. This ADR is `D-0037`.

## Decision

### 1. Ease model

`Ease` stays `Copy` and keeps `Eq`/`Hash`. A cubic-bezier curve is stored as
`BezierEase { x1, y1, x2, y2 }` with each control value quantised to one
millionth and held in `i32`:

- `x1` and `x2` are validated in `[0, 1]` (otherwise the curve is not a
  function of time); `y1`/`y2` may overshoot, up to `|y| <= 2000`.
- Non-finite values are rejected.
- `-0.0` canonicalises to `0`, so two curves are equal exactly when their
  displayed numbers are equal and `Hash` agrees with `Eq`.
- The quantisation is documented on `BezierEase`; `mdf_value()` renders the
  canonical `bezier(x1, y1, x2, y2)` form.

New named eases and their exact formulas (Penner):

| Name | Formula |
|---|---|
| `hold` | `0` for `t < 1`, `1` at `t == 1` |
| `elastic_out` | `2^(-10t) * sin((t - p/4) * 2π/p) + 1`, `p = 0.3` |
| `bounce_out` | `n t²`, `n (t - 1.5/d)² + 0.75`, `n (t - 2.25/d)² + 0.9375`, `n (t - 2.625/d)² + 0.984375` for the four `1/d`, `2/d`, `2.5/d` bands, `n = 7.5625`, `d = 2.75` |
| `expo_in_out` | `0.5 * 2^(20t - 10)` below 0.5, `1 - 0.5 * 2^(-20t + 10)` above |
| `sine_in_out` | `(1 - cos(πt)) / 2` |

The bezier solver is deterministic: up to eight Newton–Raphson steps from
`t = x`, then a fixed 64-step bisection fallback. There is no time- or
platform-dependent branch. Accuracy is `|x(t) - x| < 1e-9` on the supported
range and the tests pin CSS `ease`, `ease-in-out` and an overshooting curve.

### 2. Motion blur

`comp(..., motion_blur=False, shutter=180, samples=8)`:

- `shutter` is in degrees and must lie in `(0, 360]`; `samples` must lie in
  `1..=64`. Anything else is a span-carrying DSL error.
- Sub-frame times are centred on the frame:
  `t_i = frame + (shutter/360) * ((i + 0.5)/samples - 0.5)`, with equal
  weights.
- The evaluator gains `evaluate_fractional(document, frame, time, plan)`. The
  integer `evaluate` path calls it with the exact `f64` conversion of the
  frame, so existing goldens (including `hello_f120.png`) stay byte-identical.
- `still` and `render` honour the setting. The editor preview has it off by
  default; `motion_blur_preview(on)` toggles the indicator and the state flag.
- Rendering goes through the engine accumulation API (D-0038), never a CPU
  readback. While the pin predates that API the render path returns the typed
  `RenderError::Unsupported` under the `engine-accumulation` feature being off.

### 3. Helpers

Both helpers emit ordinary keys, so they are deterministic, overridable and
bakeable.

- `stagger(nodes, property, values, start, step, duration, ease)`: `values` is
  a list of `(from, to)` pairs, one per node; a single pair is shared by every
  node. Node `i` gets a linear key at `start + i*step` with `from` and a key at
  `start + i*step + duration` with `to` and `ease`.
- `node.wiggle(property, seed, frequency, amplitude, start, end)`: one key per
  `1/frequency` seconds, `sine_in_out`, value `base ± amplitude`. `base` is the
  property's current static value (existing keys are not sampled). The PRNG is
  SplitMix64: `state = seed`, each step adds `0x9E3779B97F4A7C15`, mixes with
  the two SplitMix64 multipliers and uses the top 53 bits as a uniform
  `[0, 1)` number. The same seed always produces the same keys.

### 4. Editor

- The ease grid shows the new presets with their curve thumbnails.
- A selected key with a bezier ease shows its four numbers; `set_ease` /
  `ease` / `key` accept `bezier(...)` and the new names.
- The overrides file, `bake` and `query` round-trip every ease through
  `Ease::mdf_value()` / `mdf_literal()`.

## Consecuencias

Gana:

- One deterministic easing model that covers CSS curves and the common Penner
  presets, with `Eq`/`Hash` that stay honest.
- Motion blur is GPU-averaged in linear light, so black/white at 0.5/0.5 is
  sRGB 188, not 128.
- The integer evaluation path is unchanged, so existing goldens are safe.
- `stagger` and `wiggle` are plain keys: no new runtime concept to bake.

Se pierde:

- Bezier values are quantised to 1e-6; a curve authored with more precision is
  rounded. The displayed numbers are the source of truth.
- `wiggle` uses the static value as its base, not the sampled value at
  `start`; animating a property that already has keys needs an explicit
  offset instead.
- The live preview indicator is wired but the preview does not yet run the
  accumulation pass; `still`/`render` are the reference.

Pendiente:

- Turn `engine-accumulation` on after the pin bump (D-0038) and regenerate the
  motion-blur golden from the clone.
- A full four-field bezier editor (the numbers are shown read-only today;
  `set_ease(bezier(...))` edits them).
