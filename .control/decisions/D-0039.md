## Contexto

D-0036 makes MDF code the training material for a small Motioner model, and
D-0040 defines that corpus. A 1–3B model is weak at coordinate arithmetic,
at converting musical timing to seconds and at keeping a palette consistent
across fifty statements. Today MDF only offers primitives (`rect`, `text`,
`key`, `stagger`, `wiggle` from D-0037), so every program re-derives layout,
timing and style by hand, and a model has to get all of it right every time.

The language should carry the design knowledge so that the shortest program
is also a beautiful one. The library must exist **before** the corpus is
generated; a corpus written against the primitives would have to be
regenerated.

## Decision

### 1. Shape

- The standard library is written **in MDF** wherever the language allows it
  (`std/*.motion`, shipped with the app and versioned with the language), and
  in Rust only where MDF cannot express it (text measurement, theme lookup in
  constructors). Readable library code is itself training material.
- It is an implicit prelude: its names are available without `use`. A user
  definition shadows a prelude name, and `motioner lint` warns about it.
- **Everything compiles to ordinary nodes and keys.** No new runtime concept:
  rendering, `query`, overrides, bake and write-through work unchanged.
- The library is **read-only for write-through** (D-0036): an edit to a value
  produced inside `std` goes to the argument of the user's call (for example
  `at=beat(2)` → `at=beat(3)`) or to a local assignment after it, never into
  `std`.
- `std` has a version tied to the MDF version. Breaking changes need a
  migration (`motioner migrate`) because trained models depend on it.

### 2. Themes (design tokens)

`theme(name, **overrides)` returns a token set and `use_theme(t)` makes it the
default for the program:

- colours: `bg`, `surface`, `text`, `muted`, `accent`, `accent_2`, `success`,
  `warning`, `danger`, with WCAG AA contrast between `text`/`bg` and
  `text`/`surface` checked at theme load;
- type: `display` and `body` families, a type scale `h1`, `h2`, `h3`,
  `body`, `caption`, `label` (sizes for 1080p, scaled by composition height),
  weights, tracking;
- spacing scale `xs`, `s`, `m`, `l`, `xl` and radii;
- motion tokens: `tempo` (bpm) and eases for `enter`, `exit`, `move`,
  `emphasis` (D-0037 curves).

Constructors accept tokens: `text("Hi", style="h1")`, `fill="accent"`
(a colour string without `#` is a token name), `gap="m"`. Hex values and
pixels stay valid everywhere. The first release ships 8–12 curated themes
(dark, light, editorial, playful, corporate, neon, pastel, mono...), each
reviewed visually.

### 3. Relative layout

- Composition-relative placement: `node.place(anchor, x=None, y=None,
  margin=None)` with anchors `center`, `top`, `bottom`, `left`, `right` and
  corners; `x`/`y` as fractions of the composition (0–1); `safe_area`
  (action safe 5%, title safe 10%) is the default margin for text.
- Containers that measure their children: `row(nodes, gap, align)`,
  `column(nodes, gap, align)`, `grid(nodes, cols, gap)`, `stack(nodes)`
  (centred overlay). Results are static positions computed when the program
  runs, using the same text measurement as the renderer (D-0035
  `LayoutData`), so layout and pixels never disagree.
- `node.bounds()` exposes the measured box for custom layout.

### 4. Time in beats and scenes

- `tempo` comes from the theme or `comp(..., tempo=120)`; `beat(n)` and
  `bar(n)` (four beats) return seconds. Every time argument still accepts
  seconds.
- `scene(name, start, length)` returns a group that is visible only inside
  its window (hold keys on `visible`) and has `scene.t(x)` to turn
  scene-local times into absolute ones. Scenes make a program read like a
  storyboard, which is also the plan format of D-0040.

### 5. Motion presets

Methods on nodes, all emitting plain keys with theme eases and durations in
beats:

- `node.enter(kind, at, duration=None, ease=None, **params)` and
  `node.exit(kind, at, ...)`: `fade`, `rise`, `drop`, `slide` (`from_=left
  |right|top|bottom`), `pop` (overshoot scale), `zoom`, `blur` (effect),
  `wipe` (mask), `draw` (trim path), `spin`;
- `node.emphasis(kind, at, ...)`: `pulse`, `shake`, `wiggle`, `glow`,
  `bounce`;
- `node.move_to(pos, at, duration=None)`: eased move with the theme `move`
  ease;
- text: `text.reveal(kind, at, by="char"|"word"|"line", stagger=None)` over
  the D-0034 text animators: `fade`, `rise`, `type`, `mask_up`, `scramble`
  (deterministic seed);
- groups: `enter_all(nodes, kind, at, stagger)` and `exit_all(...)` built on
  `stagger` (D-0037);
- `count_up(text_node, from_, to, at, duration, format)` for numbers.

Defaults are chosen by visual review, not by formula, and recorded in the
library docs with a GIF per preset.

### 6. Components

`std/components.motion` grows a small set of reviewed building blocks, each
a function returning a group with named parts: `card`, `title_card`,
`lower_third`, `logo_lockup`, `badge`, `button`, `bar_chart`, `progress`,
`background(kind)` (gradient drift, grain, glow orbs). Components take theme
tokens and never hard-code colours.

## Consecuencias

Gana:
- Short programs that look good by default; fewer tokens and fewer errors
  for a small model; consistent style across the corpus.
- Layout and timing errors (off-screen text, unreadable holds, random
  durations) become rare because the defaults are right.
- The plan written in comments (D-0040) maps one-to-one to `scene` blocks.

Se pierde:
- A large API surface to design, document, version and keep stable.
- Presets can make videos look alike; themes, parameters and components must
  be varied enough, and the corpus must also contain hand-built motion.
- Text measurement enters the interpreter through a trait; the DSL stays
  engine-free and file-system-free, but the measurement provider must be the
  same in preview, render and tests.

Pendiente:
- Exact names and defaults are fixed in the implementing prompt after a
  visual review of every preset and theme.
- Whether components live in the prelude or need `use("std/components")`.

## Addendum (2026-11-07, prompt 13b C0)

### Final preset defaults

After the visual review and the `check_design` pass, the shipped defaults are
(`crates/motioner_dsl/std/motion.motion`):

| Preset | Defaults |
|---|---|
| `enter` rise / drop | 56 px / 72 px, distance is `distance` when given |
| `enter` slide | 180 px, side `left` (also `right`, `top`, `bottom`) |
| `enter` pop | scale 0.72 -> 1.0 with `back_out`, opacity on the first 0.35 beats |
| `enter` zoom | scale 1.18 -> 1.0, opacity on the first 0.35 beats |
| `enter` blur | blur radius 22 -> 0 px, opacity across the full duration |
| `enter` wipe | `scale.x` 0 -> authored scale |
| `enter` draw | `trim_end` 0 -> 1 (path nodes only) |
| `enter` spin | rotation -24 deg -> authored rotation, opacity in 0.35 beats |
| `exit` | the mirror of `enter` for fade, rise, drop, slide, pop, zoom, blur, spin |
| `emphasis` pulse | +12 % scale, half-way peak, theme emphasis ease |
| `emphasis` bounce | 46 px rise with `bounce_out` |
| `emphasis` shake | six decaying x offsets (-14, +12, -9, +6, -3, 0) |
| `emphasis` wiggle | rotation, 7 samples, 2 deg amplitude, 3 Hz |
| `emphasis` glow | radius 28, intensity 0 -> 1 -> 0 |
| `move_to` | position keys with the theme `move` ease |
| `reveal` | stagger 8 % of the duration per character (22 % per word, 40 % per line) |

Every duration is in beats (four beats per bar; tempo 120 unless the theme or
`comp(tempo=...)` says otherwise). Eases come from the theme motion tokens:
`enter`, `exit`, `emphasis` and `move`. The visual review produced one GIF per
preset in `out/std/presets/` and the optimized copies in `docs/std/presets/`.

`check_design` runs over every preset and component on a 1000 x 600 board
with the default arguments: `crates/motioner_analysis/tests/presets.rs`
asserts zero errors on three themes, and the release matrix example covers
the ten themes (see the prompt 13b report for the images).

### count_up deviates from section 5

Section 5 sketched `count_up(text_node, from_, to, at, duration, format)`.
MDF text content is static: there is no animatable string channel and the
renderer prepares glyphs once per node. Rather than add a new document
channel in this prompt, `count_up(to, at, duration, from, steps, prefix,
suffix)` returns a group with one text layer per step (default 24, capped at
60) and switches them with `hold` opacity keys. It is deterministic, compiles
to ordinary nodes and keys, works with query/overrides/write-through, and
`check_design` accepts it. The cost is one layer per displayed value; a truly
animatable text channel is still the right long-term fix and is recorded as
backlog (T-DSL-0024).

### Themes and components

The ten themes and their boards are final; the boards live in
`out/std/themes/` and `docs/std/themes/` (1600 x 1000). Components stay in
the implicit prelude (no `use`), because every component is a pure function
over the theme tokens and keeping them implicit is what makes the shortest
program designed. User definitions still shadow them and `lint` warns.

### Scenes

`scene(name, start, length)` keeps compiling visibility to opacity hold keys
(the document has no animatable visibility channel). Named groups appear in
the outline and the timeline as labelled rows; the remaining gap is a
dedicated labelled range in `project_summary`, tracked in T-DSL-0024.
