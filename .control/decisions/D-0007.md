## Contexto

The document can be changed by the UI, the AI agent, the code layer and
background jobs. If any of them mutates state directly, undo, validation,
review, audit and collaboration semantics break. Silent state changes
also make debugging and reproducibility impossible.

## Decision

Every document mutation is a typed command with a validated
precondition, an inverse and a human-readable summary. Commands are
grouped into transactions.

- UI actions emit commands.
- AI tools map one-to-one to commands.
- Code edits compile to commands.
- Background jobs operate on immutable snapshots and produce new
  versions through commands where they commit changes.
- Undo, redo and review operate on transactions, not raw diffs.

## Consecuencias

Gains:
- Complete undo and audit coverage.
- Reviewable AI changes with diffs and provenance.
- Validation centralized in one place.
- A stable API for UI, AI and automation.

Costs:
- Every feature must define its command and inverse.
- More boilerplate than direct field mutation.
- Some bulk operations need careful transaction grouping.

Pending:
- Specify the command schema and transactional boundaries.
- Decide how long AI transactions stay open for review.
- Define conflict behavior for background commits.
