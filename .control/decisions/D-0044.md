## Contexto

A real showcase exposes 472 layers named "Circle 1..300" in a flat list. The
editor cannot rename them readably, cannot collapse or filter a group, has no
value graph for a channel and rebuilds/lays out every row on every frame. The
1000-layer target also needs a measured steady state, not a guess.

Write-through (D-0036) will later turn every UI action into an MDF edit, the
standard library (D-0039) will name generated bindings, and the agent tools
(D-0043) publish the same command surface. Names, filters, graph actions and
the performance work must therefore be ordinary `Command`s and ordinary
document fields, not private editor state.

## Decision

### 1. Display names are a node field, identity is untouched

`Node` gains `display_name: Option<String>`, written by `node.name = "..."` in
MDF, by the `name` override and by `rename(id, name)`. `NodeIdentity` (explicit
`.id()` or provenance) never changes. `query` reports the display name;
`bake` writes `var.name = "..."` for a bound node and keeps an override when
the node has no top-level binding.

After a run, a naming helper assigns a default name to nodes that do not have
one: the first variable they are bound to (`title = text(...)` → `title`), or
that name plus the full index path, outermost first. A loop iteration adds its
index (`dot 2 5` for outer 2 and inner 5; a single loop stays `dot 3`) and a
user-function call adds its invocation ordinal (`holder 2`), so nested loops
and repeated calls never collide. The helper is public so the write-through
planner can reuse it for new bindings.

### 2. Outline: collapse, filter, solo and shy

- `collapse` (the chevron) hides a group's descendants in the layers panel and
  the timeline. It is editor state, not a document property.
- `filter_layers(text)` matches the display name, kind and identity
  case-insensitively and keeps the ancestors of every match visible.
- `solo(id, on)` and `shy(id, on)` mark layers; `show_shy(on)` is the global
  switch. Solo hides every other layer from the **preview**; shy hides the
  marked layer unless shy layers are shown. The renderer skips those nodes
  through one `paint_visible` entry point, so `render` and `still` never see
  editor state and exported pixels are unchanged.

### 3. Graph editor

One numeric channel is opened from a timeline row (`graph_open(id, property)`,
double click). Keys are points; a segment whose arriving key has a `bezier`
ease gets two draggable control points. Dragging a handle sends one `ease`
command with the new `bezier(...)`; `x` is clamped to `[0, 1]` and the D-0037
quantisation applies. Dragging a key sends `move_key_value(id, property, from,
to, value)`. Named eases draw their curve read-only; double clicking such a key
converts it to a close cubic-bezier via `ease`. `graph_view`/wheel/pan change
only the view. Every edit is a normal `Command` with parity coverage and a
`docs/agents.md` entry; a drag is one gesture and one undo step.

### 4. Performance

- Timeline and outline rows are virtualised: layout emits only the rows that
  intersect the visible area, into a reusable buffer (no per-frame `Vec`).
- Visibility runs and key summaries are computed once per document generation
  and stored on the outline row; collapsing and filtering only toggle flags.
- Timeline/outline drawing keeps no per-frame formatting: value texts, channel
  labels, the identity lookup, all header/ruler strings and the graph caption
  are cached and rewritten in place. An optional `alloc-count` feature installs
  a **per-thread** counting allocator (the UI thread only, so GPU workers do
  not pollute the reading); the status bar always shows the counter when the
  feature is on, including a zero.

  Measured on the reference machine with `timing.motion` at 1600x900, thirty
  frames in, collapsed outline: **9 allocations per frame, 4 in the layers
  panel and 5 in the timeline**. They are not Motioner string work: the engine
  builds a fresh `GuiBatch` every frame
  (`engine/ferrous/crates/ferrous_engine/src/runner/frame.rs:316`), so its quad
  and text vectors grow from zero for the chrome that is drawn. Reusing that
  batch across frames is an engine change (same pin-bump flow as the rest of
  D-0023); until it lands the honest reading is 9, not zero. The `/9` is the
  engine batch, not the timeline model.
- The motion-blur preview runs the **same** accumulation function as `still`
  and `render` through a headless frame renderer, capped at four samples while
  playing and the full sample set while paused.

## Consecuencias

Gana:
- Big scenes are readable (names, collapse, filter, solo/shy) without touching
  identity, overrides or rendered pixels.
- Graph edits use the same undo, write-through and agent command path as the
  inspector.
- Steady-state cost is bounded by what is on screen, and the counter makes a
  regression visible instead of anecdotal.

Se pierde:
- Editor state (collapsed groups, filter, solo/shy, graph view) lives outside
  the program; D-0036 records it in the project editor state file later.
- The motion-blur preview allocates a second offscreen renderer and a readback
  when enabled, so it is a preview aid, not the 60 fps playback path.
- The graph only edits numeric channels; colour and discrete fields keep the
  inspector.

Pendiente:
- Write-through naming and structural edits reuse the naming helper (prompt
  12).
- The optional counter is a development tool; it is intentionally off by
  default.
