## Contexto

D-0022 keys nodes without `.id()` by the byte offset of their creating call
(plus call sites and loop indices). Editing any line above a call shifts the
offsets, so its overrides become orphans. Prompt 08 left open whether to
change the key to something less sensitive (line-relative, call-path based)
or to add a re-binding tool.

Alternatives considered:

- **Line/column keys**: still shift when a line is inserted above; only
  same-line edits stop shifting. Little gain, same failure.
- **Call-path keys** (the n-th `circle(...)` call in function `f`): stable
  under unrelated edits but ambiguous when calls are added or reordered, and
  a silent re-match to the wrong node is worse than a visible orphan.
- **Content hashes**: rejected in D-0022 (the same program must give the
  same keys across runs and index remaps).

## Decision

Keep byte-offset provenance keys unchanged. Orphans stay visible (warning,
orphans list, `query` → `orphans`) and are re-bound explicitly:
`assign_id(from, to)` moves every override of one identity to another, from
the editor's command layer (`motioner edit`, `motioner ctl`, D-0024). The
recommended path for nodes that are edited often remains `.id("name")`.

No automatic `motioner rebind` heuristic is added now; an agent can do it
with `query` (old ids in `orphans`, candidate nodes with kind, name and
values in `nodes`) and `assign_id`, and decide case by case.

## Consecuencias

- No change to existing overrides files; no risk of silent re-matching.
- Editing the program above edited nodes still orphans overrides until they
  are re-bound or the nodes get an `.id()`.
- The hybrid bake (T-DSL-0006) must re-key remaining overrides after it
  edits the program in place.
- Revisit if users hit orphans often: a suggestion list (same kind, same
  creation order, nearest offset) shown next to each orphan is the next step.

## Addendum (2026-11-01): suggestions and re-binding

The "next step" of this decision is now implemented:

- `Editor::orphan_suggestions()` / `suggestions_for()` rank the live nodes a
  lost identity most likely belongs to. Candidates must accept the property
  and must not already be targeted by another override of the same property.
  The uniform provenance shift of the program edit is inferred from the
  orphans and the live nodes; the closest shifted key wins (base call offset,
  then `/c` call-site offsets and `/i` loop indices, i.e. the same creation
  order, then the parent's offset, then creation order).
- `query` adds `"suggestions": ["@id", ...]` to every orphan, best first.
- The orphans list of the layers panel offers a Rebind action that runs the
  existing `assign_id(orphan, best_suggestion)`; there is no new command.
- The hybrid bake uses the exact offsets of its own in-place edits instead
  (D-0027): suggestions are for edits made outside bake.
