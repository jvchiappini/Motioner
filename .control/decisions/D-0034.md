## Contexto

Phase 7 turns text from one Roboto line into a typographic feature: a shipped
family with weights, real block layout (tracking, line height, `\n`), CPU
measurement for the DSL, and character animation for kinetic type. The pinned
engine (`e8b9ba7`) only has single-line layout with legacy `kern` kerning; the
engine branch adds `GPOS` pair kerning and block layout, so the Motioner side
ships behind a temporary `engine-text-layout` feature exactly like Phase 6.

## Decision

1. **Family: Inter, OFL 1.1, static 400/600/700.** `assets/fonts/` ships
   `Inter-Regular.ttf`, `Inter-SemiBold.ttf`, `Inter-Bold.ttf` and `OFL.txt`
   from Inter 4.1. Total asset cost: 1,251,812 bytes (~1.22 MiB) plus the 4,380
   byte licence. Inter is metrically stable, has a large glyph set and ships
   GPOS pair kerning without a `kern` table, which is exactly the case the
   engine parser must handle. Roboto Regular stays embedded as the bundled
   fallback; it is what every golden before Phase 7 uses.

2. **Lookup.** `font="Inter", weight=600` resolves in two stages:
   1. project `assets/fonts/` (case-insensitive family and style suffix);
   2. the fonts bundled in the renderer (Inter 400/600/700 and Roboto 400).

   A missing family is `RenderError::FontFamily { family, searched }`, and
   `searched` lists every path/name tried. A family present without the exact
   weight resolves to the **nearest weight** and records a typed warning
   (`FontWarning::NearestWeight { family, requested, used }`) that `query` and
   the inspector surface. This is a warning, not an error: a document still
   renders with the closest face instead of failing at frame 0.

3. **Measurement stays engine-free at the core boundary.** `motioner_core`
   defines `TextMetrics`:

   ```text
   measure(&self, request: &TextRequest) -> Option<TextMeasurement>
   ```

   `TextRequest` carries the string, size, family, weight, tracking,
   line height and alignment. `TextMeasurement` carries width, line count,
   height, ink bounds and per-line advances. `motioner_render` implements the
   trait with the same `ferrous_font` layout the renderer uses (CPU only, no
   GPU device); `motioner_io` loads the font bytes and builds the registry;
   `motioner_dsl::run` receives `&dyn TextMetrics`. Core, DSL and eval remain
   file-system-free and engine-free. `text_width`/`text_bounds` therefore
   measure exactly what is drawn instead of guessing advances.

   *Pin note:* `e8b9ba7` has no block layout and no GPOS. Until the bump the
   Motioner measurer reproduces the block formula on top of the pinned
   single-line layout, so `text_width` is exact for Roboto single lines (the
   showcase fix) and best-effort for GPOS-only fonts. The bump replaces that
   shim with `measure_block`.

4. **Per-character animation is a text animator on the node, not
   `split_chars`.** A split would multiply nodes, break edits to the string and
   lose the one-node mental model. `node.animate_chars(property, from, to,
   start, stagger, duration, ease, order=...)` appends a `TextAnimator` to the
   text node. Properties: `opacity`, `offset` (x/y), `scale`, `rotation`,
   `color`. `order` is `forward`, `reverse` or `center`.

   - Animators are ordinary document data: serializable, overridable through
     `<name>.overrides.motion`, bakeable and visible in `query`.
   - **Spaces count for the stagger.** Every character entry of the layout
     advances the stagger index; whitespace simply produces no quad. This
     keeps source order and offsets stable when a word is edited, and avoids a
     second notion of "visible index".
   - The evaluator carries the node's animator list into the plan (an arena
     index) together with the frame; the render adapter walks the same
     `ferrous_font` layout, applies each animator per glyph and draws with
     `draw_glyphs_2d`. Measurement and drawing therefore share one glyph
     order, and the per-glyph result is deterministic.
   - `order="center"` ranks glyphs by distance to the block centre (rounded
     down on ties), so the middle appears first.

5. **DSL.** `text(..., font="Inter", weight=600, tracking=0.02,
   line_height=1.2)`; `tracking` and `line_height` are animatable channels with
   stopwatches in the editor, and `weight` is discrete. `\n` inside the string
   is a line break. `text_width(content, size, font="Inter", weight=400,
   tracking=0)` and `text_bounds(...)` are pure builtins backed by the metrics
   trait; `text_bounds` returns `(left, top, right, bottom)` in Motioner local
   pixels (y down, the baseline origin at `(0, 0)`).

6. **Pin gap.** All real styled drawing, block layout and per-character draw
   calls live behind `engine-text-layout` (off by default). With it off,
   rendering a node that needs multi-line text, non-zero tracking or a text
   animator returns `RenderError::Unsupported { feature: TextLayout }`; a
   single-line Roboto node with no tracking still renders exactly as before.
   The feature is removed when the pin carries the engine layout.
   *Amended 2026-11-02:* pin 06a8adf carries it; the feature, the precheck
   and the refusal test are gone, and the typography comparison runs.

7. **Goldens.** `typography_tracking_fNN.png`, `typography_lines_fNN.png` and
   `typography_chars_fNN.png`, generated from the clone with the feature on,
   plus `tests/golden_typography.rs` with pinned SHA-256, per-beat overlap/gap
   pixels and the D-0028 render comparison. `hello_f120.png` and every earlier
   golden stay byte-identical: Roboto without tracking lays out exactly as
   before.

## Consecuencias

- A project can add a font by dropping a TTF under `assets/fonts/`; no code
  change, no rebuild of the engine. Weight matching is forgiving but visible.
- `text_width` and `text_bounds` now depend on a metrics implementation being
  passed to the interpreter. `motioner_dsl::run` keeps its old signature and
  returns a runtime diagnostic from those builtins when no metrics are
  installed; every Motioner binary installs one.
- Character animation is deterministic (frame, layout order and easing only),
  survives text edits and bakes into ordinary animator calls.
- The engine learns GPOS `PairPos` kerning and block layout as public,
  documented features with no Motioner names, so the pin bump removes only the
  temporary feature, not any document or editor code.
