## Contexto

MDF v0 animates only the five transform channels. `fill`, `stroke`,
`stroke_width`, `width`, `height`, `radius` and text `size`/`color` are
static, which is the single biggest visual limit of `examples/showcase.motion`:
a professional motion-graphics piece animates colour palettes, draws lines on,
morphs shapes and moves masks. Every later phase of the professional-motion
job (gradients, effects, masks, images, typography) adds more animatable
properties, so the model has to be fixed once, up front, instead of being
reinvented per feature.

## Decision

The shared model below is accepted. Phases implement it incrementally; no
phase may contradict it without a superseding ADR.

### 1. Animatable content properties

A node property is either a scalar channel (`Animatable<f64>`), a colour
channel (`Animatable<Color>`), an optional colour channel
(`Animatable<Option<Color>>`), or a non-animatable value (text string, align,
font family, asset path). The document stores the *property* (static value
plus keys); `motioner_eval` samples it into the render plan.

Property names are the override names of D-0022, so `key("fill", ...)`,
`override_key("id", "fill", ...)`, bake, `query` and the editor channel table
all speak one vocabulary:

| Node kind | Animatable content fields |
|---|---|
| rect | `width`, `height`, `radius`, `fill`, `stroke`, `stroke_width` |
| circle | `radius`, `fill`, `stroke`, `stroke_width` |
| text | `size`, `color`, `tracking`, `line_height` |
| path (Phase 2) | `trim_start`, `trim_end`, `trim_offset`, `dash`, `dash_offset` |

Content fields have no axes: none of them is a 2D vector, so the editor keys
them as whole channels (`fill`, not `fill.x`).

### 2. Colour interpolation space

Colour keys interpolate in **linear-light sRGB**, per channel, including
alpha. Stops and text colours are authored as 8-bit sRGB (`#rrggbb[aa]`) and
converted to linear for interpolation; the result is converted back to 8-bit
sRGB for the render plan. `Animatable<Option<Color>>` interpolates normally
when both endpoints are present; when either endpoint is `none` the value
holds the previous colour as a step, so clearing a fill with `"none"` snaps at
that key instead of fading through an undefined colour.

Rationale: the engine already composites in linear light
(`crates/motioner_render/src/space.rs`), so a linear midpoint is the one that
keeps a keyed gradient perceptually continuous with an alpha blend of the same
two colours. OKLab was rejected because (a) it hue-shifts midpoints relative
to what the compositor does one layer below, so a keyed fill and a stacked
alpha gradient of the same stops would disagree, and (b) it needs a 3×3
transform per sample for no benefit at 8-bit output.

The comparison is rendered by `out/color_space_compare.motion`: six pairs of
colours, each shown once as the engine's linear-light midpoint (animated
`fill`) and once as the naive sRGB midpoint (hard-coded literal). The result
is `out/color_space_compare.png`; regenerate with
`motioner still out/color_space_compare.motion --frame 30 --out out/color_space_compare.png`.

### 3. Effect stack

`node.effect(kind, **params)` appends one ordered effect to a node. The stack
is per node, ordered bottom to top, and applies to the node and its whole
subtree: a node with effects renders its subtree into an offscreen layer,
applies each effect in order, then composites with the node's accumulated
opacity and blend mode. Every parameter is a normal animatable property with
a name under the effect (`drop_shadow.blur`), so `key`, `edit`, overrides,
bake and `query` work on it with no special cases. `Node.effects` is a
`Vec<Effect>` in `motioner_core`; the render pass mapping lives in
`motioner_eval` (plan) and `motioner_render` (execution).

### 4. Masks

`node.mask(other, mode="alpha"|"luma", invert=False)` sets one mask node per
node (the mask node is not drawn itself; its subtree is). The mask keeps its
own animatable transform, so a moving rectangle reveals moving text. The mask
reference lives in `motioner_core` as an optional `MaskRef`; render uses
stencil or an offscreen alpha multiply, both deterministic.

### 5. Blend modes

The list and the exact formulas are fixed (premultiplied alpha, source `S`,
backdrop `B`, all in linear light; `c` is the blended colour and `a` the
coverage):

| Mode | `c` (premultiplied inputs) | Coverage |
|---|---|---|
| normal | `S` | `Sa + Ba·(1-Sa)` |
| add | `S + B` (clamped) | `Sa + Ba·(1-Sa)` |
| multiply | `S·B` | same as normal |
| screen | `S + B - S·B` | same as normal |
| overlay | `S < 0.5 ? 2·S·B : 1 - 2·(1-S)·(1-B)` | same as normal |
| darken | `min(S, B)` | same as normal |
| lighten | `max(S, B)` | same as normal |

Blend modes are non-separable only in the future (hue/saturation); the list
above is the v1 set and matches CSS/After Effects for these modes.

### 6. Assets

An asset is a project-relative path (`assets/…`), resolved by
`motioner_io` (never by core/DSL/eval, which stay file-system-free). Bytes are
hashed (SHA-256) and the hash keys the decode cache and the GPU texture cache.
Missing or undecodable assets are typed errors (`RenderError::Asset`), never
panics; the DSL reports a missing font/asset as a diagnostic at load time.

### 7. Golden frames

Pixels depend only on the document and the integer frame. Each new feature
gets at least one golden still in `crates/motioner_testkit/golden/`. Comparison
policy: exact for pure geometry unit tests; for GPU renders no channel may
differ by more than 2 and at most 0.1 % of pixels may differ by more than 2
(the same policy as `hello_f120.png`). Effect goldens use the same tolerance;
a feature whose output is not stable across adapters within that tolerance
gets a wider documented tolerance in its test, never a skipped assert.

## Consecuencias

Gana el proyecto: one animatable property model for content, gradients,
effects and assets; agents get every new property through the existing
`set`/`edit`/`key`/`unkey`/`stopwatch` commands; the editor keeps one channel
table; and colour animation matches the compositor.

Se pierde: content fields are no longer `Copy` plain numbers, so every reader
must decide whether it wants the static value or the sampled one, and the
document grows one keyframe vector per animated field. Optional colours hold
instead of cross-fading; fading a fill out needs a keyed alpha instead of
`"none"`.

Queda pendiente: per-glyph text animators (Phase 7), gradient stop animation
(Phase 3) reuses this model but needs a `Gradient` value type, and the
`tolerance` of future GPU effects is only measured when those phases land.
