## Contexto

The recent-project cards must show a relative age ("5 min ago",
"yesterday") and a tooltip with the full **local** date. `motioner_io`
already formats UTC (`format_utc_seconds`) without a dependency, but the
standard library exposes no local offset, and the workspace denies
`unsafe_code`, so a direct Win32 call is not acceptable.

## Decision

Add `time` 0.3 (MIT/Apache-2.0) to `motioner_io` only, with the
`local-offset`, `formatting` and `parsing` features. Relative ages are a
pure function of the stored RFC 3339 text and an injected `now`
(`motioner_io::relative_time`), tested at the boundaries. The tooltip uses
`OffsetDateTime::parse` plus `UtcOffset::current_local_offset`, falling
back to UTC on hosts where the offset cannot be determined.

Why writing it is worse: a correct local-offset implementation is
platform-specific (Win32 `SystemTimeToTzSpecificLocalTime`, the IANA
database elsewhere) and needs `unsafe`, while `time` keeps the conversion
in safe, audited code and provides an RFC 3339 parser.

Cost: `time` pulls `deranged`, `num-conv`, `powerfmt` and `time-core`
(small, pure Rust). It is not on the render path; only the start screen
and the recent list call it.

## Consecuencias

Gana: relative ages and full local tooltips without `unsafe`; a pure,
injected clock makes the boundary tests exact.

Se pierde: one more dependency in `motioner_io`. If the local offset is
unavailable the tooltip falls back to UTC, which is still a full date.
