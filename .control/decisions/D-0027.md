## Contexto

D-0022 bakes overrides by appending `var.property = value` statements, which
only works for nodes bound to a top-level variable. Nodes created in loops or
functions (the five circles and the two spinners of `hello.motion`) keep their
overrides forever. T-DSL-0006 asked for a hybrid bake: edit the program in
place when that is exact, keep overrides otherwise.

Editing text in place is exact only when the value came from one literal that
belongs to that one node. A literal inside a loop, inside a function called
twice, or shared through a variable feeds several nodes; changing it would
silently change them all.

## Decision

### Value origins

The interpreter records, for every property write it performs, a
`ValueOrigin`: the node, the property as written, the source span of the
expression that produced the value, whether that expression is a plain
literal (number, string, two-number pair, bool, `None`), the write kind
(static or a key at a frame) and, for keys, the explicit `ease` argument.

Origins are recorded from three places, all in the DSL:

- constructor arguments (`rect`, `circle`, `text`) as static values;
- `node.property = value` assignments as static values, unless the assignment
  is augmented (`+=`, `-=`…), where the result is computed;
- `node.key(property, time, value, ease)` calls as keyframe values.

The recorder replaces an earlier static value or key of the same node and
property, so the last write wins exactly like the document. Recording is
deterministic and never changes the document.

### Private literal

A literal is **private** to a node when the recorded span appears exactly
once in the run. The count is the number of recorded origins sharing that
span start: a loop body or a function called twice records the same span once
per node, so the count is the number of nodes it feeds. A default parameter
that was never written has no span and is never edited.

### Bake order

For each override, in file order:

1. **In place** when the node has a matching origin, its literal is private
   and the override value has the same shape (number, string, pair, bool):
   replace the literal text with `format_number`, `quote`, `(x, y)`,
   `True`/`False` or `None`. A key also edits the `ease` string literal when
   the call has one; when it has none, the override must keep the default
   linear ease. Nothing is appended for that entry.
2. **Generated block** otherwise: the D-0022 behaviour (`var.property =
   value`, `var.key(...)`), which still reaches bound nodes with shared or
   computed values.
3. **Refusal** when neither is possible (orphans, loop-created nodes without
   a binding, names, locks, unkeys); the override stays with a reason that
   also says when the literal was shared.

### Re-keying

Replacing a literal changes the program length, so every byte-offset
provenance key after the edit shifts. The edits are sorted by source offset
and applied from the end; every remaining override's key has each embedded
offset (`@call`, `/c<call-site>`) moved by the sum of the edit deltas that
end before it. `/i<iteration>` indices do not move. Explicit `.id()` names
are untouched. This is exact by construction: the edit offsets are known, so
no heuristic is needed (the Phase 2 suggestions are for edits made outside
bake, not for this).

### Exactness

Before returning, bake re-runs the candidate program with the remaining
overrides. If it does not compile, has override warnings, or its composition
differs from the expected one, the in-place pass is discarded and the
historical behaviour is used. Provenance identities are compared by position,
not by text: an in-place edit legitimately renumbers them, and the overrides
that stay were re-keyed to the new numbers.

## Consecuencias

- Private literals are folded for any node, bound or not; shared literals are
  refused with a reason. The circles of `hello.motion` keep their overrides.
- Bake stays exact and idempotent; the `agent_parity` and DSL bake tests
  compare the re-bound document semantics and override text.
- Baking a title colour, size or a private key no longer appends a block; the
  program shows the value where the user sees it.
- An in-place bake can renumber provenance keys later in the file. Any
  override that stays is written with the new keys in the same atomic write,
  so no orphan is produced.
- The interpreter pays one small struct per property write for the lifetime
  of a run; measurements on `hello.motion` are in the phase report.
