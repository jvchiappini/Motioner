## Context

Prompt 17 fixed startup; prompt 18 (P0-P7) made the rest of the engine
and the editor measured and wasteful work deliberate: an idle screen
must not render, a steady-state frame must not allocate, a cache must
have an owner and a byte budget, and every claim must be a number.

This decision records the standing policy and closes `T-PERF-0001`
(superseded: its budgets and benchmark plan were delivered by
`T-PERF-0005` and the `scripts/perf_bench.py` harness). It also records
why Motioner's chrome uses retained batch ranges rather than the engine's
`UiSystem`, the comparison P4 asked for.

The reference machine is REF-0003 (Ryzen 5 8645HS, 8 GB RAM, RTX 4050
Laptop 6 GB + Radeon 760M, Windows 11). Every number in this policy was
measured on it in release, 1600x900, with `scripts/perf_bench.py`
(median of three back-to-back runs, one warm-up discarded).

## Decision

### 1. Measure first, and keep the instrument

- `ferrous_core::alloc_stats` (feature `alloc-stats`, counting global
  allocator + thread-local `FrameScope`) counts allocations, bytes and
  frees per frame on the frame thread, with worker counts separate.
- `ferrous_core::frame_trace` (`FERROUS_TRACE_FRAMES=1`) reports the nine
  frame stages (event, update, layout, collection, batch, prepare, encode,
  submit, present), their median/p90/p99, `frame_ms`, the per-frame GPU
  counters (`draw_calls`, passes, pipeline/bind-group/buffer binds,
  scissors, GUI segments), `input_to_present_ms`, `ui_damage`,
  `memory_report` and the per-owner `memory-owners` line.
- `scripts/perf_bench.py` runs the eleven scenarios (idle start/editor,
  hover, static hover, scrub, 1080p and 4K30 playback, heavy UI, the
  3,000/1,000-layer lists, heavy composition, export) and
  `--check scripts/perf_budgets.json` fails when a median exceeds its
  budget. Budgets are the measured median + the P0 15 % noise margin,
  with absolute floors for near-zero metrics. The zero-allocation tests,
  the idle-runner tests and the flat-inventory test run in the normal
  gate; the budget check and the divan bench baselines
  (`scripts/bench_baselines.json`) are the reviewer's commands.
- An optimisation without a before/after number on the same scenario is
  not accepted.

### 2. On-demand redraw

`RedrawPolicy::OnDemand` is the default for the editor: a frame is drawn
when input arrives, when the app calls `request_redraw`, when a scheduled
`redraw_at` fires, when a worker wakes the loop, or on resize/scale/theme
changes. Continuous mode stays for games, demos and benchmark fixtures.
An idle window presents 0 frames and submits 0 GPU work after its first
frame; the residual 0.1-0.3 % of a core is the NVIDIA user-mode driver
(nvoglv64/nvwgfx2umx), attributed by thread start address, not our loop.

### 3. Zero allocations per frame

Steady-state frames allocate nothing on the heap. Buffers are reused with
`clear()`, grown geometrically, and only shrunk by an explicit trim
policy. Tests assert 0 frame-thread allocations after warm-up for the
engine UI frame, the Pure2D frame, the Motioner editor frame and the
Motioner playback frame. Strings on frame paths are interned, static or
cached by value; a `format!` on a frame path is a bug.

### 4. Byte budgets, compact formats and ownership

- Every cache has a byte budget, an eviction policy and an inventory
  entry (font atlases and layout cache, decoded images, mesh and
  tessellation caches, panel/row batches). The flat-inventory test runs
  the heavy scene and asserts the inventory is flat after warm-up.
- GPU formats use the smallest representation that keeps the goldens
  byte-identical: packed colours, `u16` indices where the vertex count
  allows it, `R8` for coverage/SDF atlases, `RGBA8` only where MSDF needs
  it.
- CPU copies are dropped after upload unless a named owner needs them
  (readback, re-pack, export); the owner is recorded.
- Textures are deduplicated by content hash; the 2D target is lazy and
  the GUI depth attachment is disabled outside 3D.

### 5. Hashing

Hot maps use `rustc-hash` (`FxHashMap`/`FxHashSet`) with integer or
interned-id keys. SipHash stays for cold/security-sensitive work. The
choice is recorded here once and applies to the whole workspace; a
cryptographic hash on a frame path is a finding.

### 6. When our own algorithm replaces a library

Keep a library by default. Replace it only when a bench on our workloads
shows a clear, repeatable win and the replacement is no less readable
(the margin is stated in the phase report). Our own code is welcome for
workload-specific loops: layout/font caches, the ASCII text fast path,
the path tessellation cache, the eval static-subtree cache, the culling
flags and the segment coalescer all won on their benches. lyon stays for
tessellation; the best-fit atlas packer was measured and rejected because
it changed the goldens.

### 7. Retained batch ranges, not `UiSystem` (Motioner chrome)

Motioner's editor paints its chrome directly into a `GuiBatch`; it never
uses `UiSystem`/`RenderCollector` (P4 finding). Two options were planned:
move the panels onto `UiSystem`, or keep the direct painter and add
retained per-panel/per-row ranges. The retained ranges were chosen:

- The editor already owns the frame batch and the paint order; moving to
  `UiSystem` is a full painter rewrite with a large golden-risk surface,
  not an incremental win.
- The P6 measurement is decisive: per-panel/per-row caches with
  `GuiBatch::extend_from` give heavy_ui_list **0.154 ms** collection at
  3,000 layers (flat vs 1,000), hover at the P3 frame budget, scrub
  collection **1.735 ms** (target <= 1.8) and heavy_ui **23 draws / 14
  segments** from 62/38 before the coalescer. A rewrite would have to beat
  those numbers to justify the risk.
- The comparison is not closed forever. Change the choice if the
  retained ranges stop being enough for a feature `UiSystem` already has
  (for example, an editor panel that needs the engine's layout, clip-aware
  spatial index and retained clean-subtree commands as one unit), or if a
  measured panel exceeds its budget after a fair public-API attempt. Record
  the new numbers and reopen this decision before rewriting.

Residual known limit: expanded timeline property rows still include the
playhead frame in their key, so they rebuild on scrub; layer rows and the
timeline chrome replay.

### 8. Offscreen present

The engine exposes an opt-in persistent offscreen present path
(`AppConfig::persistent_ui`, per-frame damage under a break-even). The
safe implementation repaints the whole composition and GUI into a
persistent texture and copies/blits it to the swapchain, so it is
pixel-identical. It is **off by default**: the clean back-to-back A/B
(P7) measured it **31.8 % worse on scrub** and **66.8 % worse on hover**
(heavy_ui +2.4 %, within noise), because it adds a full-image copy to
every frame. It stays available for a future true partial update
(`LoadOp::Load` + scissored damage repaint), which is the change that
would make it win. A win under 10 % of CPU does not justify enabling it.

### 9. A measurement is only valid with its sample

Every CPU % in a before/after table is the median of three back-to-back
runs with the min/max range next to it. A full-suite sample that drifts
(e.g. a 182.7 MB VRAM outlier in a 50.8 MB scenario) is re-measured in a
focused back-to-back run before it is used in a decision or a budget.

## Consequences

- `T-PERF-0001` is closed as superseded; its budgets and benchmark plan
  live in `scripts/perf_budgets.json`, `scripts/bench_baselines.json`,
  the engine `performance.md` page and this decision.
- The gate gains a performance guard (budget check + recorded bench
  baselines) and keeps the zero-alloc, idle and flat-inventory tests.
- A future partial redraw or a `UiSystem` migration must reopen this
  decision with numbers, not replace it silently.
