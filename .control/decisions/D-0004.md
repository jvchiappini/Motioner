## Contexto

The editor needs an After Effects-like workspace: docking, tree views,
virtualized timeline rows, a bezier keyframe editor, text editing with
syntax highlighting, context menus, color pickers and drag and drop.
FerrousEngine ships its own UI stack (ferrous_gui, ferrous_ui_core,
ferrous_ui_render, ferrous_layout). The user also maintains GUIMaker, a
separate project that owns the engine UI toolkit and will provide the
updated repository later.

## Decision

Confirmed by the user on 2026-10-31.

Build the editor chrome on the engine-native UI stack: Ferrous UI and
GUIMaker. Do not use egui.

- GUIMaker is a separate project, not vendored in this repository; it is
  pinned like FerrousEngine when it is integrated.
- The editor's docking, panels, timeline rows, keyframe graph, code
  editor and chat are implemented on top of GUIMaker widgets.
- Widgets missing for an editor (docking, virtualized lists, bezier
  graph, syntax-highlighted text) are contributed to GUIMaker when they
  are generic, and kept in `motioner_ui` when they are editor-specific.
- The viewport is rendered by FerrousEngine into a texture and displayed
  by the UI; picking uses an ID buffer.

## Consecuencias

Gains:
- One rendering and UI stack, one device and one event loop.
- The custom engine and the editor evolve together.
- No second toolkit or wgpu version mismatch.

Costs:
- Significant widget work before the editor feels complete.
- The editor's schedule depends on GUIMaker maturity.
- Generic widgets must be upstreamed and maintained.
