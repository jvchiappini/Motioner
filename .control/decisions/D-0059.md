## Contexto

E3 gave path points a keyable geometry channel and geometry drivers. The
mascot still needs the HTML `apply()`'s body corners, bulges and shape
variants without baking every corner by hand. These are deformations of the
authored outline, not more points: they must run once per frame after
drivers and before constraints, and be shareable by bake and a future
runtime.

## Decision

Add `motioner_rig::deformer` with three pure deformers.

1. **Lattice**: a 2x2 control net with four Vec2 corner properties and four
   optional Vec2 edge-midpoint offsets. The source is the part's local
   bounds. Each point is mapped through a Coons patch whose edges are
   quadratic curves; handles map by the same patch and become relative
   offsets again. Points outside the bounds are clamped to `0..=1`. A lattice
   reuses the authored topology.
2. **Skin**: a hierarchy of bones with bind position/rotation, length,
   optional rotation/position properties, and either explicit per-point
   `(bone, weight)` lists or deterministic auto-weights (inverse squared
   distance to the bind segment, top two bones, normalized). Each point is
   linear-blend-skinned in bone space; handles rotate by the same bone delta.
3. **Blend shapes**: named target point lists with a number weight property.
   Weights blend point-wise in declaration order. `compatible_points`
   resamples any target polyline to the part's point count along arc length,
   so `fit=True` provides the topology helper; without it a mismatch is a
   typed error.

Deformers run in declaration order after scalar/geometry drivers. Every
deformer writes only `PartOutput::geometry`; transforms stay in the
driver/constraint stages. The bake then writes the resulting points as
ordinary geometry keys (D-0058).

Noise/spring eases are not part of this decision; spring follow-through is
D-0060.

## Consecuencias

- The pipeline is properties/machine -> drivers -> deformers -> constraints
  -> bake keys. One implementation in `motioner_rig` is shared by bake and
  future playback.
- Lattice, skin and blend shapes are structure declarations in source;
  their continuous parameters (corner offsets, edge bends, weights, bone
  rotations) are ordinary rig properties, so existing property write-through
  covers them.
- Lattice and skin preserve the point count; a topology change is never
  silent. Blend shapes can be fitted explicitly.
- Auto-weights are a deterministic starting point, not a substitute for
  authored weights; explicit weights are accepted by `m.skin`.
- The mascot with a lattice plus geometry drivers measures **0.041
  ms/frame** for a full load (parse + 900-frame bake) on the reference
  machine, well under the 0.3 ms/frame target.
- Textured mesh deformation of images/video remains E5.
