## Contexto

Prompt 16 needs SVG symbols (any SVG becomes an editable symbol). The
candidates were `usvg` (a full parser with its own tree and features),
the engine's `ferrous_svg`/`lyon_svg` (whose `svgparser 0.8.1` already
triggers a future-incompatibility warning and which the engine does not
expose as a stable generic feature), and an in-house parser for the
subset Motioner's node model can represent.

Motioner's model is a tree of groups and single-subpath path nodes with
fill/stroke, gradients, masks and effects. A general SVG AST would have
to be translated into that model anyway, and both candidate parsers
bring dependencies whose maintenance and warning profile are outside
this project's control.

## Decision

- Write a **zero-dependency SVG reader** in `motioner_io`
  (`svg.rs` + a small XML tokenizer) that maps SVG to
  `motioner_core::Symbol`: groups, `path` (M/L/H/V/C/S/Q/T/A/Z, absolute
  and relative; arcs converted to cubics with a documented tolerance),
  `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, transforms
  (`translate`, `scale`, `rotate`, `matrix`, `skewX/skewY` flattened
  into geometry), `fill`/`stroke` (colour, width, cap, join, miter,
  dashes), `fill-opacity`/`stroke-opacity`/`opacity`, linear and radial
  gradients, `defs`/`use`, `clipPath` (instantiated as a D-0033 mask),
  `viewBox`/`preserveAspectRatio` (scale and centring), and element ids
  or `inkscape:label`/`data-name` labels as part names.
- Unsupported constructs (text as text nodes, filters, patterns,
  multiple subpaths in one `d`, embedded images) produce warnings that
  name the element id, never a silent drop. Multiple subpaths are split
  into numbered child parts under the same id.
- SVG geometry is flattened into Motioner coordinates at import
  (transform applied to points) so golden documents do not depend on a
  transform stack; parts that need animation are authored around a pivot
  that is recorded as the node anchor.
- Fidelity tests compare flattened point sets and rendered rasters
  against committed reference PNGs produced once from the reference
  mascot and hand-authored Figma/Illustrator/Inkscape-style files. No
  `resvg` dev-dependency is added; reference PNGs are committed fixtures.

## Consecuencias

Gana:
- No new dependency, no future-incompatibility warnings, full control of
  the mapping and of diagnostics.
- The parser is small enough to test in isolation and to extend when a
  real SVG needs a feature.

Se pierde:
- Feature coverage is deliberately smaller than a full SVG engine; CSS
  styling, filters and text-to-path conversion are not supported.
- Arc flattening introduces a bounded geometric error (documented in the
  test tolerance).

Pendiente:
- Evaluate `usvg` again if a user file exposes a needed feature the
  subset cannot represent; the ADR records why it was not chosen now.

## Addendum - prompt 16b E0 (2026-11-11)

`vector-effect="non-scaling-stroke"` is honoured. SVG does not inherit the
property; Motioner does, so the root or a group can opt a whole symbol in.
`PaintSpec::non_scaling_stroke` stores the placement scale the width is
authored at (the symbol instantiation multiplies it), and `motioner_render`
moves the points to composition space and strokes there, which is the only
way a non-uniform squash cannot flatten one side of the outline. It is a
document-model field but not an animatable channel. No new dependency.

Reason: until the E3 geometry channel re-derives the mascot's paths, a
driver scales the mouth to 6 % of its height and the outline collapsed to a
hairline. The mascot root opts in, so every authored line keeps its weight
relative to the instance.
