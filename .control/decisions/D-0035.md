## Contexto

Phase 8 adds raster images to a motion-graphics editor whose documents are
program-first and whose pixels must be deterministic.  D-0028 section 6
already fixed the asset model (project-relative paths, SHA-256 keys, bytes
loaded by `motioner_io`, core/DSL/eval file-system-free); it left the image
format, geometry, cache lifetime and failure behaviour open.

## Decision

**Formats.** PNG is the required format and goes through the workspace `png`
crate in `motioner_io`.  The decoder expands palette, greyscale and 16-bit
images to straight-alpha RGBA8 (16-bit keeps the high byte).  `gAMA` and
`iCCP` are ignored: every image is treated as sRGB, like every other colour in
the document.  JPEG and WebP are out until a dependency ADR justifies them;
the engine's optional `image` feature is not a reason by itself.

**Paths.** Only project-relative paths are accepted.  An absolute path or a
`..` component that leaves the project is a DSL/loader error with a span (the
DSL stores the path; the loader validates it).  The project root is the
process working directory, the same root `assets/fonts/` uses.

**Caching.** `motioner_io::ImageStore` reads the bytes, hashes them with
SHA-256 and decodes once.  The hash is the content key: the same file at two
paths is one texture, and a changed file is a new key.  Core, DSL and eval
never read a file; `Document::resolve_images` only consumes the
`ImageResolver` trait.  The renderer registers textures with mipmaps on first
use and reuses them by key across frames; `texture_bytes_2d()` reports the
resident bytes.

**Geometry.** `image(source, width=None, height=None,
fit="contain"|"cover"|"fill")`.  `width`/`height` are the destination box in
pixels; `None` (or `0`) means natural.  No size uses the pixel size; one
dimension keeps the aspect from the other.  `contain` letterboxes inside the
box (transparent outside), `cover` fills the box and crops through `uv_rect`,
`fill` stretches.  The anchor is the centre.  `width`/`height` are animatable;
`fit` and `source` are discrete.

**Missing or invalid file.** `still`/`render` fail with
`RenderError::UnresolvedImage { source }` before drawing.  The preview draws a
checker plus an outline placeholder and reports the path as a warning; it never
crashes.  A texture above the device limit or the byte budget is a typed
`RenderError` (`Image`, `TextureBudget`).

**Layers and effects.** Images go through the same painter-order stream as
shapes and text, so opacity, transform, blend, effects and masks apply exactly
as for any other node.  The engine's drop shadow uses the layer alpha, so
transparent texels cast no shadow.

## Consecuencias

Gana: one asset model for fonts and images, content-addressed textures, real
fit modes, and a preview that degrades to a placeholder instead of failing.
Agents get `set`/`edit`/`key` for `width`/`height`/`source`/`fit` through the
existing command layer.

Se pierde: images are sRGB-only (no colour management), PNG-only, and a
changed file needs a reload/new `ImageStore` to be re-hashed.  The 4K source
in the mipmap check is decoded on the CPU once; very large images trade memory
for decode time.

*Amended 2026-11-02:* pin e0cc574 carries `LayoutData` and
`register_texture_2d`. The temporary `engine-images` and
`engine-layout-data` features, the `Unsupported` path for images and the
parser measurement fallback are gone. The example badge is 256 px drawn at
160 px so the goldens cover the mip chain.

Pendiente: JPEG/WebP need their own dependency ADR; an asset file picker is a
UI concern the command layer cannot express yet; the live preview uploads
textures lazily but the editor does not yet show a per-image memory readout.
