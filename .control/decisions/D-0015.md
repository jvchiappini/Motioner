## Contexto

The user wants a public, free, Apache-2.0 project that still generates
income. Apache-2.0 prevents selling the open core as a proprietary
product and allows competitors to use the code, so revenue must come
from adjacent value.

## Decision

Approved by the user on 2026-10-31.

Revenue comes from optional services and products around the open core,
in this order:

1. Donations and sponsorships.
2. Paid cloud rendering and encoding.
3. Paid AI credits with provider routing and budgets.

Priority support, training and a future asset/effect marketplace are
later options. The open-source editor remains fully usable offline with
the user's own API keys. No core capability is paywalled.

## Consecuencias

Gains:
- Compatible with Apache-2.0 and community trust.
- Revenue scales with usage, not with feature locks.
- Multiple independent income sources.

Costs:
- Requires hosted infrastructure and payment handling.
- AI credit margins depend on provider pricing.
- Marketplace moderation and payouts add complexity.

Pending:
- Which source is prioritized first.
- Hosting provider and cost model.
- Pricing and free-tier limits.
- Whether cloud rendering is part of 1.0 or later.
