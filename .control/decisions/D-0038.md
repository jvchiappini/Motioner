## Contexto

Motion blur needs several sub-frame renders averaged in linear light. Doing
that on the CPU after an 8-bit readback loses precision and stalls the GPU
once per sub-frame. The engine had no generic "average N renders" primitive;
the only similar code was the layer compositor, which is tied to Motioner's
layer model.

## Decision

Add a generic `Accumulation2d` to `ferrous_2d` and mirror it on
`Renderer`, `Pure2dHarness` and `RenderContext`:

- `begin_accumulation_2d()` clears an `Rgba16Float` target and resets the
  weight sum.
- `accumulate_frame_2d(weight)` samples the finished output target, scales all
  four premultiplied linear channels by `weight` and adds them with an
  additive blend.
- `resolve_accumulation_2d()` writes `sum / total_weight` into the normal
  output target, so the existing readback returns it.

The API is typed and never panics: `NotBegun`, `ZeroWeight`, `InvalidWeight`,
`TooLarge` and `Unsupported` (outside the Pure2D mode). The order is fixed
(clear, one full-screen triangle per sub-frame in call order, one resolve), so
identical calls are byte-identical on the same adapter.

The pin is still `e0cc574`, which predates this API. Motioner keeps the
render hook behind the `engine-accumulation` feature (off by default) and
returns the typed `RenderError::Unsupported` while it is off. The reviewer
bumps the pin, turns the feature on and regenerates the motion-blur golden.

## Consecuencias

Gana:

- Motion blur, supersampling and any other "average N renders" effect share
  one deterministic GPU path.
- No CPU readback per sub-frame; the average is exact in linear light.

Se pierde:

- One extra target-sized `Rgba16Float` texture while a sequence is open.
- The source target must have `TEXTURE_BINDING` usage; the headless
  `OffscreenTarget` gained it.

Pendiente:

- The pin bump and the feature-on golden (D-0037).
