## Contexto

Projects contain compositions, animation data, effects and large media
assets. They must be portable, diffable, crash-safe and migratable. The
user prefers a Motioner-owned format over adopting RON, JSON or a
database, and D-0011 makes the MDF program the canonical source, so the
project stores MDF programs rather than a separate serialization.

## Decision

Confirmed by the user on 2026-10-31.

Use a Motioner-native text format as the canonical project format. The
same grammar, parser and printer serve both the on-disk document and the
code panel; there is no second serialization format.

- Project folder: `<name>.motioner/`.
- `project.motion` - manifest with format version, settings, asset
  registry and composition references.
- `compositions/<slug>.motion` - one file per composition, in the native
  format.
- `assets/<hash>.<ext>` - immutable, content-addressed blobs.
- `cache/` - decoded assets and frame caches, safe to delete.
- `backups/` - autosave and recovery snapshots.
- A packed single-file archive may be added later for sharing.

Format rules:

- Every file starts with a format version and is validated on load.
- Serialization order is deterministic so version-control diffs are
  meaningful.
- Unknown fields are rejected with a clear error, never silently
  dropped; migrations run explicitly.
- Assets are immutable; editing one produces a new hash.
- The format is owned by Motioner and may evolve with the language; it
  is not coupled to serde, RON or JSON.
- Phase 1 defines a minimal MDF v0 that covers the Phase 1 fixture;
  later phases extend the same grammar rather than introducing a new
  format.

## Consecuencias

Gains:
- One format for disk, code and AI: strong DRY and round-trip fidelity.
- Full control over syntax, diagnostics, versioning and migrations.
- Human-readable, diffable projects.
- Deduplicated, immutable assets.

Costs:
- We own the parser, printer, formatter, fuzzing and migrations.
- A parser bug is a project-corruption risk; validation and atomic
  writes are mandatory.
- Text parsing cost at load time, irrelevant for the render hot path.

Pending:
- Specify the MDF v0 grammar and its mapping to the document AST.
- Define the packed archive format and compatibility promise.
- Define atomic write, backup and recovery behavior.
- Define relinking rules when a project moves between machines.
