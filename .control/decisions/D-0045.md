## Contexto

D-0005 fixed the project folder at a conceptual level (a `.motioner/`
directory, content-addressed assets, MDF as the only format) but left the
concrete contract open. Prompt 11 needs that contract before any code:
Phase 1 writes the loader, Phase 2 the start screen, Phase 3 the asset
registry and Phase 4 autosave/backups. Without one written contract every
phase would invent its own manifest fields, resolution order and failure
modes.

## Decision

The project folder is `<name>.motioner/` and this is its v1 contract.

### Layout

```
<name>.motioner/
  project.motion          manifest (format version, settings, registry,
                          composition list, main composition)
  compositions/<slug>.motion
  compositions/<slug>.overrides.motion   (only while overrides exist)
  assets/<sha256>.<ext>   immutable blobs
  cache/                  decoded media, peaks, proxies, thumbnails (deletable)
  backups/                rolling snapshots (deletable)
  traces/                 reserved for D-0036 write-through traces
  editor.motion           editor state: layout, locked, expanded rows,
                          last frame. Never rendered.
```

Only `project.motion` and the files under `compositions/`, `assets/` and
`editor.motion` are authoritative. `cache/`, `backups/` and `traces/` may be
deleted at any time; the project still opens. A `.motioner` folder is
recognised by `project.motion` (a folder without it is not a project).

### Manifest (`project.motion`)

A plain MDF program of constant calls, one call per line, so the same
parser, printer and diagnostics serve project files (D-0011):

```
project(version=1, name="demo", width=1920, height=1080,
        fps=60, duration=600, background="#000000", main="main")
asset(key="logo", hash="<sha256>", file="logo.png", kind="image",
      original="logo.png", imported="2026-11-03T10:00:00Z")
composition(slug="main", title="Main")
```

- `project(...)` is mandatory and appears once. `version` is the format
  version; `main` names a composition slug.
- `asset(...)` appears zero or more times, sorted by `key`.
- `composition(...)` appears at least once, sorted by `slug`.
- Unknown calls, unknown keyword arguments and duplicate keys are rejected
  with a diagnostic carrying the file and line. Unknown fields are never
  silently dropped (D-0005).
- Serialization order is fixed: `project`, then `asset` by key, then
  `composition` by slug. Saving a loaded project twice is byte-identical.

### Asset registry

One entry per blob: SHA-256 content hash, original file name, importer
kind (`image`, `font`, `audio`, `video`), import date (UTC, seconds) and a
stable human key. The key starts as the original file stem, is
case-insensitively unique and gets a numeric suffix on a clash (`logo`,
`logo-2`, ...). The key, not the path, is what MDF names.

### MDF surface

- `image("logo.png")`, `audio("music.mp3")`, `video("clip.mp4")` resolve
  through the registry **by key or original name**, project assets first.
  A bare name that matches no registry entry is still tried as a
  project-relative path (`assets/fonts/Inter.ttf`, today's behaviour).
- `asset("logo")` is the explicit form and takes the key only; an unknown
  key is a load error.
- `resolve` records the asset key on the node (`ImageContent.asset`), so the
  renderer never re-resolves a path per frame.

### Project root

The project root replaces the process working directory used by D-0034 and
D-0035 for `assets/fonts/`, images and any other project file. Fonts resolve
from `<root>/assets/fonts/` first, then the bundled set. A loose
`.motion` file keeps today's behaviour: single-file mode root = the process
working directory, no registry, no autosave. `motioner edit`/`bake` on a
loose file still writes `<stem>.overrides.motion` next to it.

A project is opened either by its folder (`demo.motioner`), by its
`project.motion`, or by one of its composition files; all three resolve to
the same root. Every CLI command accepts any of the three.

### App-level state

`%APPDATA%\Motioner\app.motion` (MDF constants, same rules):

```
app(version=1, window_width=1600, window_height=900,
    window_x=0, window_y=0, maximized=false)
recent(path="C:/work/demo.motioner", name="demo", opened="2026-11-03T10:00:00Z")
```

Recent entries are capped at 12, most recent first, and a missing folder is
kept (shown greyed with "remove") rather than silently deleted. On a
non-Windows machine the same file lives next to the user's config
directory; the app crate owns the path.

### Writes, validation and migrations

- Every write is atomic: temp file in the same directory, fsync, rename.
  A leftover temp file is garbage collected on open, never trusted.
- Load validates the version first, then the grammar, then the references
  (main composition exists, every asset file exists and hashes as recorded
  when cheap; a mismatch is a typed error naming the asset).
- Migrations are explicit functions keyed by source version. v1 has none;
  an unknown newer version fails with `UnsupportedVersion` instead of
  guessing.

## Consecuencias

Gana: one written contract for all seven phases, deterministic diffs, a
registry that makes MDF names stable when files move, and a single root
notion shared by fonts, images, audio and video. CLI and UI share the same
loader, so a project that opens in the app renders from the terminal.

Se pierde: the manifest is hand-parsed MDF constants rather than a free
program, so new fields need a parser arm; keys are frozen at import (renaming
a file in Explorer does not rename its key); app state is MDF too, which is
more code than an INI but keeps one grammar.

Pendiente: migrations for v2, the packed archive, relinking by original
name after a machine move, and the write-through trace format (D-0036).
