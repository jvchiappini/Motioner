## Contexto

D-0028 section 3 fixed the *model* of the effect stack (`node.effect(kind,
**params)`, ordered, keyable params, applied to the node and its subtree) but
not how it renders. Phase 5 had to decide what an effect does to pixels, where
the passes live, and how a deterministic GPU implementation is tested.

The engine's offscreen layers (D-0031) already render a subtree into a texture
and composite it with opacity and `CompositeMode2d`. Effects can reuse exactly
that machinery if they are expressed as operations on the finished layer image,
instead of as a new kind of draw.

## Decision

1. **Effects are a property of a layer, not of a draw.** A node with a
   non-empty effect chain renders its whole subtree into an offscreen layer;
   the chain runs over the finished texture, then the layer composites with the
   node's opacity and blend mode. A node without effects keeps the previous
   path.

2. **Chain semantics.** Effects run in stack order, each one reading the
   previous image:

   - `Blur { radius }` replaces the image with its Gaussian blur.
   - `DropShadow { color, offset, blur, opacity }` blurs the image, tints it,
     offsets it and puts it **behind** the image.
   - `Glow { color, radius, intensity }` blurs the image, tints it and **adds**
     it as light around the image.

   Textures are linear and premultiplied. The shadow is
   `shadow = (color.rgb, 1) * color.a * opacity * blurred.a` and
   `out = content + shadow * (1 - content.a)` (shadow behind; amended 2026-11-02, the first version put it over the content); the glow is
   `out = content + vec4(color.rgb * color.a * intensity * blurred.a, 0) * (1 - content.a)`
   (outer glow; amended 2026-11-02, the first version also lit the content and
   turned a dark shape into a blob of glow colour).

3. **The Gaussian kernel is a pure function of the radius.** `sigma = radius /
   2` (CSS `box-shadow` / canvas `shadowBlur`; amended 2026-11-02 from
   `radius / 3`, which read about a third as strong as users expect),
   `taps = ceil(1.5 * radius) + 1` clamped to 76 one-sided samples, weights
   `exp(-i^2 / 2 sigma^2)` normalized so the centre plus both wings sum to 1.
   A zero or non-finite radius is the identity (one tap). The kernel is built on
   the CPU, uploaded as a uniform and unit-tested; the GPU never recomputes it.
   Blur is separable: one horizontal and one vertical full-target pass.

4. **Engine API (general, Motioner-agnostic).** `Effect2d` (the three variants
   above), `BlurKernel2d`/`gaussian_kernel`, `Layer2d` plus
   `Renderer::push_layer_2d_with_effects(desc, &[Effect2d])` and the harness
   equivalent; `LayerError::InvalidEffect` and `TooManyEffects` (8 per layer).
   Docs: `crates/ferrous_2d/docs/effects.md`.

5. **Pass layout.** With `n` effects the renderer runs at most `3n` passes plus
   one copy: two blur passes per blur, and a tint/offset composite per shadow or
   glow. Two full-target scratch textures per layer ping-pong with the layer
   texture, so the layer's own texture is the starting point and the final
   destination; the existing composite path and its cached bind group stay
   untouched. Pass uniforms use one pooled buffer per pass (writing a single
   shared buffer would let the last encoded pass win, because
   `queue.write_buffer` is ordered against submission, not against passes).

6. **Motioner representation.** `Node.effects: Vec<Effect>` (one per kind) in
   `motioner_core::effect`; parameters are ordinary animatable channels named
   `<kind>.<param>` (`.x`/`.y` for `offset`). Evaluation samples the chain into
   `PlanLayer.effects`; the plan also carries the item range each layer wraps,
   so nested groups and effects nest correctly. The editor stores the stack as
   one `effects` override (a comma-separated kind list) which rebuilds the stack
   while preserving parameters; `effect_add`, `effect_remove` and `effect_move`
   are commands, parameter edits and keys use the generic `set`/`edit`/`key`
   with the dotted name.

7. **Pin gap.** The pinned engine (e9fb90d) has no effect passes. Until the pin
   moves, Motioner answers with `RenderError::Unsupported { feature: Effect,
   node }` before painting. The golden still `effects_f0.png` is committed and
   validated by its own pixel assertions; the render comparison
   (`golden_effects.rs::effects_match_the_golden`) is ignored with that reason.
   *Amended 2026-11-02:* pin 7a9b7fd carries the passes; `paint_plan` maps
   `EffectValue` to `Effect2d` and calls `push_layer_2d_with_effects`, the
   precheck and the `Unsupported` test are gone and the comparison runs.

8. **Golden policy.** Same tolerance as D-0028 (max channel diff 2, at most
   0.1 % of pixels above 2). The still is generated from the clone with the
   temporary adapter wiring and the exact same example; the fixture's SHA-256
   is pinned in the test.

## Consecuencias

Gana el proyecto: one deterministic effect vocabulary for agents and the
editor, built on the layer machinery that already exists; no new render graph
node or per-draw pass; the kernel is testable off-GPU and the passes are
testable on-GPU with exact pixel values (shadow interior, glow intensity, zero
radius, group opacity). Blur and shadow add no state outside the per-layer
scratch pool.

Se pierde: a layer with effects costs two full-target scratch textures and up
to three full-target passes per effect; very large radii clamp at 48 px; the
glow is additive light behind the content without extra coverage (by design).

Queda pendiente: Phase 9's motion blur can reuse the same layer chain; per-effect
masks are a Phase 6 concern.
