## Contexto

The D-0043 catalogue stores JSON Schema per tool, the CLI accepts
`--args '<json>'` and the batch runner replays JSONL, so the tool runtime
must parse arbitrary JSON into typed parameters and validate results against
their schema. `motioner_ui::Json` is a small write-only encoder built for
`query`/`edit`; hand-writing a parser and a schema validator would be a
second JSON implementation to keep correct.

`serde_json` is already in `Cargo.lock` through the pinned engine, is
Apache-2.0/MIT, and is the de-facto schema vocabulary (JSON Schema itself is
JSON).

## Decision

- `motioner_tools` uses `serde_json` (with `preserve_order` off) for tool
  arguments, results and the JSON Schema documents it publishes. The engine
  already carries it, so no new transitive crate enters the graph.
- The tool descriptors remain plain Rust data structures; `serde_json` only
  serialises them. No `serde` derive is required in the catalogue, which
  keeps the public API readable.
- `motioner_ui::Json` stays the writer for `query`/`edit`/`ctl` and is not
  replaced: those have golden output tests and no parsing needs.

## Consecuencias

Gana:
- Exact schema validation and replayable batches with a maintained parser.
- No new dependency version to audit.

Se pierde:
- Two JSON writers coexist (write-only `Json` for the editor protocol,
  `serde_json` for tools); documented here so nobody duplicates a third.

Pendiente:
- If `serde` derive ever becomes useful for tool results, adding the derive
  is a minor change under this ADR.
